# Скиллы

Задачи и требования до кода — `/backlog`. Процесс изменений — `/dev` и пять шагов; общее для всех шагов — [architecture/PROCESS.md](/architecture/PROCESS.md).

**Скилл — только шаги:** прочитать, запустить, показать, спросить, записать. Что нельзя сделать скриптом — строкой «руками: …». «Почему» и истории — в `architecture/PROCESS-WHY.md`; шаблоны документов и брифов — в `templates/` папки скилла; проверки, нужные не всегда, — отдельными файлами в папке скилла; скрипты — `architecture/tools/dev*.py`, у бэклога `backlog.py`.

Формат проверяет `validate-skill.py` (`.claude/.instructions/skills/.scripts/`, полный список — его шапка): шапка `name`, `description` от 100 до 600 знаков, `allowed-tools`; один заголовок H1; до 15 000 знаков; верхний нумерованный список шагов, первый — «Прочитать»; последняя строка — «**По ходу всех шагов:** …»; без историй, дат и цитат.

Рабочая сессия скиллы не правит: только запись в журнал (`PROCESS.md`, раздел 12).

| Скилл | Что делает |
|-------|------------|
| [dev](./dev/SKILL.md) | Где мы и следующий шаг изменения (вызывать в начале сессии и на «продолжи») |
| [dev-start](./dev-start/SKILL.md) | Задача и решения решающего до описания |
| [dev-describe](./dev-describe/SKILL.md) | Описание изменения в `architecture/TOBE`: правки поверх копий «как есть», задачи, тесты, блоки; «да» решающего |
| [dev-block](./dev-block/SKILL.md) | Блок кода агентом по брифу, проверка основным вживую |
| [dev-deliver](./dev-deliver/SKILL.md) | Ревью, документы, PR, merge |
| [dev-close](./dev-close/SKILL.md) | «Как есть» заново, `done.py`, пустой TOBE |
| [backlog](./backlog/SKILL.md) | Бэклог: список задач, запись, уточнение требований, макет до кода, передача в `/dev` |
| [new-project](./new-project/SKILL.md) | Настроить новый проект из шаблона: имя, решающий, стек, `PROJECT.md`, GitHub |
| [docker-up](./docker-up/SKILL.md) | Поднять локальное окружение и проверить здоровье контейнеров |

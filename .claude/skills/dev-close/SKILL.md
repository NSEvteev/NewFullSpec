# /dev-close — закрыть изменение

Изменение сделано, когда «как есть», заново снятое с кода, совпадает с «как будет»: сделано N из N. После закрытия в `architecture/TOBE/` остаётся только `.gitkeep`. Вызов — просьба закрыть до конца, с коммитами в `main` и push: отдельно не спрашивать. Команды — из корня репо, в Bash; временное — в `$S`, папке сессии.

1. **Прочитать:** всё, что печатает `python architecture/tools/where.py --read dev-close`. Закрытие начато раньше, а сессия новая — ещё [resume.md](resume.md): где остановились.

2. **Можно ли начинать:**
   ```bash
   python architecture/tools/where.py
   git fetch origin && git status -sb | head -1 && git rev-parse HEAD origin/main
   gh pr list --state open --json number,headRefName --jq '.[] | select(.headRefName | startswith("change/")) | .number'
   ```
   Нужно: шаг «закрытие»; `## main...origin/main` без `ahead` и `behind`; два одинаковых хеша; открытых PR `change/…` нет; номер PR в поле `PR:` обложки (нет — найти `gh pr list --state merged --search <ветка>` и вписать); незакоммиченного соседа по путям изменения нет (`PROJECT.md`, «Соседние репо»); сервисы здоровы, схема базы менялась — контейнер пересоздан, общий пакет в образе совпадает с репо (`PROJECT.md`, «Живое окружение»). Не выполнено — решающему одной строкой, чего не хватает и какой скилл это делает, и стоп.

3. **Выписать изменение для себя:** обложка `architecture/TOBE/README.md` целиком, `python architecture/tools/find.py --list правка --tobe`, блоки и их `Сделано:` в `architecture/TOBE/blocks.md`. В выписке: задетые сервисы, новые и ушедшие файлы, процессы из «Последствий», проблемы «закрывает», что «уходит» и `Удаляется:`, номера PR.

4. **Код без мёртвых хвостов** — до переноса, иначе карта опишет то, что завтра удалят:
   ```bash
   python architecture/tools/build.py --check                 # «Удаляется:» против кода, секунды
   python architecture/tools/devDead.py <папки задетых сервисов>
   git show --stat <коммиты PR>                               # файлы, служившие только «уходит», удалены
   ```
   `build.py --check` пишет другие ошибки — в список находок шага 7, закрытие они не держат. Другие языки и слова, за которыми прячется оставленный код, — `PROJECT.md`, «Мёртвый код»: поиск по коду и по «как будет»; слово само не находка, находка — код, который никто не зовёт. Имя из `Удаляется:` на месте у сделанной задачи — блок не доделан, назад в `/dev-block`. Нашлось другое — закрытие остановить: решающему по смыслу (что осталось, сколько строк, почему вредно), AskUserQuestion — граница удаления, 2–3 варианта с ценой. Что удалять, решает решающий. Ответ — `/dev-describe дописать` (правка `уходит`, задача с `Удаляется:`, тест «ушло», блок), `/dev-block`, `/dev-deliver` и снова `/dev-close` с шага 2.

5. **Сервисы:** новый, ушедший или переименованный — до следующего шага по [services.md](services.md).

6. **Перенос одной командой:**
   ```bash
   python architecture/tools/map.py apply    # пробно: что перенесёт и удалит, разделы без «Код:»
   python architecture/tools/map.py close    # перенос, факты, ссылки, сверка; переименование — --rename <старое> <новое>
   ```
   `close` отвечает только тем, что править руками; что значит каждая строка и что с ней делать — [close-output.md](close-output.md). Факты он снимает без тестов: их прогнали блоки. Код сервиса менялся после блоков — `python architecture/tools/extract.py <сервис> --tests`, только основная сессия. Упавшие тесты здесь не чинить, а назвать решающему в итоге. У сервиса с `facts: []` в реестре его тесты — командой из `PROJECT.md`, число — в итог. Новые проблемы, которые велят завести решения, — после переноса, в `problems.md` сервиса.

7. **Список находок** — в чате таблицей «md · что · источник», шесть источников:
   - «без «Код:»» из вывода `close` — поставить ссылку на строку действия: перенос уже прошёл, правка в `architecture/ASIS` через Edit;
   - строка изменилась или ссылки нет — открыть код и абзац: абзац верен — `python architecture/tools/map.py accept <путь:строка>`, нет — поправить абзац; «вручную по диффу» — правка сразу во всех названных md;
   - `python architecture/tools/find.py --code --diff <коммит слияния PR>^` — описания вне правок над изменённым кодом (коммит — `gh pr view <N> --json mergeCommit`, по каждому PR): сходятся ли абзац и код. Эти абзацы никто больше не сверял;
   - каждый процесс из «Последствий» и каждый с копией в `architecture/TOBE/_processes/`, даже при чистой проверке: проверка ссылок — не проверка смысла;
   - «не сделано» из `close`: md не дословно (заголовок, якорь, id, поле) или блок не дописал имя теста;
   - закрытые изменением проблемы — ссылки на них из других md.

   Находок нет — сразу шаг 9.

8. **Правки:** основная сессия сама, Edit по md: пишется то, что в коде; якоря и id не менять; «почему» — словами, без номеров `c-…` и `d-…`, а правку, где оно осталось только в `Почему:`, дописать словами; `Код:` — на строку действия. Перенесённое не переписывается. Находок десятки в нескольких сервисах — агенты по группам md, не на всю папку: цена одной строкой решающему, ответа не ждать; запуск одним сообщением; бриф — копия [templates/brief-close.md](templates/brief-close.md). Агентов оборвала пауза — продолжать тех же (SendMessage), а живые числа и даты в их текстах перепроверить.

9. **Сведение** — отчёту агента на слово не верить:
   - `git status --short architecture/`: изменены только md из переноса и списка находок, факты и запомненные строки `.anchors.json`;
   - «для <сервиса>» и «ждёт пары» из ответов закрыть самой; `python architecture/tools/find.py --process <процесс>` по каждому задетому: участники, шаги, стрелки сходятся;
   - повторный `python architecture/tools/map.py close` — обязательно до очистки. Нужно «сделано N из N». Несделанное: md не дословно — чинить md; нет имени теста в `Тест:` — дописать в `tasks.md` имя из кода, ровно заголовок теста; в коде этого нет — назад в `/dev-block` через `/dev-describe дописать`, закрытие ждёт;
   - «сверить смысл глазами»: `close` называет число правок, сами правки — `find.py --list правка --tobe`, процессы — с обложки. Дифф: `git diff <начало>..HEAD -- <md>`, начало — `git log --diff-filter=A --format=%h -1 -- architecture/TOBE/README.md`;
   - удалённый код не упоминается: `git show --diff-filter=D --name-only --format= <коммиты PR>`, поиск каждого пути по `architecture/ASIS` — пусто;
   - выборочно: на каждом md с правками 2–3 абзаца сверить со строкой кода. Расхождение — поправить и строка в журнал: его пропустили блок или ревью;
   - `Работает ли сейчас:` задетых процессов: новые стрелки, проверенные вживую на блоках, — с датой и id; непроверенные проверенными не записывать.

10. **Документы карты:** закрытие поменяло правила или инструменты — `architecture/STANDARD.md`, `architecture/CLAUDE.md`, `architecture/project/settings.yaml`. Числа — из вывода команд.

11. **Сохранить и очистить:**
    - есть файлы `architecture/TOBE/` не в git или с правками (`git status --short architecture/TOBE`) — сначала коммит `docs(architecture): «как будет» «<название>» перед закрытием`: не бывшее в git без коммита не удалять;
    - `python architecture/tools/map.py clean-tobe` — только список. Решающему одним сообщением: сколько файлов, что папка остаётся, каким коммитом сохранено. Ответа не ждать;
    - `python architecture/tools/map.py close --finish`: сверка, очистка, места на доске и одна полная сборка. После очистки сверять не с чем: итог «N из N» — в сообщение коммита.

12. **Убрать за изменением:**
    - задачу изменения удалить: `python architecture/tools/backlog.py drop <тема>` — раздел списка, промт, папка; в задаче несколько пунктов и сделан один — убрать его через Edit, задача остаётся;
    - попутные находки — новыми задачами: `python architecture/tools/backlog.py new <тема> "<название>"`; `python architecture/tools/devChangelog.py` — строка «Изменения нет».

13. **Проверка:** `python architecture/tools/build.py --check` — 0 ошибок; `python architecture/tools/where.py` — «Изменения нет». Ошибка — чинить ровно этот md, цепочку не повторять. Бюджет на всё закрытие: `map.py apply` пробно — раз; `map.py close` — раз и раз после правок; `map.py clean-tobe` без `--yes` — раз; `map.py close --finish` — раз; `build.py --check` — на шаге 4 и здесь. Отдельные `extract.py --tests`, `relocate.py`, `live.py`, `done.py`, `clean-tobe --yes` и полная сборка — нет, всё внутри `close`.

14. **Журнал, коммиты, push:**
    - запись в журнал, если что-то пошло не так или решающий поправил ход; заголовок `### Закрытие «<название>» · <дата>`;
    - `git fetch origin && git status -sb | head -1` — `behind` есть: стоп и сказать решающему;
    - менялись инструменты, стандарт или памятка — коммит `feat(architecture): <чему научились>`;
    - коммит карты: `git add architecture/ CHANGELOG.md _backlog/` только со своими путями, `git diff --cached --stat`; сообщение `docs(architecture): «как есть» после «<название>», «как будет» закрыто`, в теле — N из N и 0 ошибок сборки. `git add -A` и `.` нельзя; хук упал — чинить причину;
    - `git push origin main`; в соседних репо коммитится только отметка шага 12.

15. **Итог решающему** — по смыслу:
    ```
    Изменение «<название>» закрыто: карта «как есть» снята заново с кода и совпадает с описанием — сделано N из N.
    Что теперь в карте: <новые сервисы и процессы; что ушло; какие проблемы закрыты>.
    По ходу нашли: <хвосты и что с ними>; тесты <сервисов> — <числа>.
    «Как будет» пусто. Коммиты: <хеши>, отправлено в origin.
    Дальше: что брать — выбираешь ты; список — `python architecture/tools/backlog.py`.
    ```
    Его вопросы и замечания — сразу в дело: решение о порядке работы — в память Claude, урок — в журнал.

**По ходу всех шагов:** решающий поправил ход, шаг не сработал или чего-то не хватило — запись в `architecture/JOURNAL.md` (вид — `architecture/PROCESS.md`, раздел 10); скилл, документы, шаблоны и скрипты процесса эта сессия не правит: не хватает инструмента — простейший обход во временной папке или вопрос решающему.

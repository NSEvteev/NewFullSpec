# /dev-close: новый, ушедший или переименованный сервис

Зачем: порядок на случай, когда изменение меняет состав сервисов. Кто читает: `/dev-close`, шаг 5, только в этом случае. Всё — до `map.py close`.

- **Новый сервис** (новая папка в `architecture/TOBE/`) — запись в `architecture/project/services.yaml`: поле `registry` его узла `new` в `architecture/TOBE/board.yaml` (поля — шапка реестра: `kind`, `root`, `facts`, `tests`, `short`…), место — перед узлами из `asis`; затем `python architecture/tools/extract.py <сервис>`. Место узла на доске перенесёт `map.py clean-tobe` из `board.yaml`.
- **Ушедший сервис** (узел `gone` в `board.yaml`) — запись из `project/services.yaml` убрать руками до `close`: иначе `close` снимает факты с сервиса без кода, а `done.py` ищет его удалённые имена не там. Папку `ASIS/<сервис>/` целиком удалит `map.py apply` — вместе с ушедшими процессами и срезами; `done.py` его `Удаляется:` ищет в коде вне живых сервисов и вне карты (compose, CI, `Makefile`, скрипты). Список ушедшего — решающему.
- **Переименованный сервис** (код, Docker и база переименованы блоком) — `python architecture/tools/map.py close --rename <старое> <новое>`: папки `ASIS/` и `TOBE/`, все написания имени в md, yaml и json карты. То, что из имени не выводится (имя базы), — `--also <старое>=<новое>`. Имя должно быть отличимым: `--rename` меняет каждое вхождение, поэтому сначала `map.py mv-service <старое> <новое>` без `--yes` — число замен. Порядок переменных и разделов по алфавиту замена не держит: сборка покажет, поправить.

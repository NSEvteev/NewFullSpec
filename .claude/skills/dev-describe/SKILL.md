# /dev-describe — описать изменение в «как будет» до кода

Порядок: решения, описание, показ, «да», код. «Да» на решение — не «да» на код. Описание нужно, чтобы решающий утвердил устройство, пока его дёшево менять, у кода и ревью было мерило, а закрытие машиной сверило сделанное с описанным. Правку по заметке агента посреди блока делает `/dev-block`. Режим `дописать: …` — [append.md](append.md). Команды — из корня репо, в Bash; `$S` — папка сессии; разрешений на чтение, сборку, проверки и агентов не спрашивать.

1. **Прочитать:** всё, что печатает `python architecture/tools/where.py --read dev-describe`; образец — `TOBE/` проверочной карты `architecture/tools/samples/good/architecture/`. Обложки нет — сначала `/dev-start`.

2. **Можно ли начинать:** `where.py` — шаг «описание»; стою на ветке из `Ветка:` (`git diff --stat HEAD <ветка>`, потом `git switch`). С начала изменения в `main` менялся код задетых сервисов (`git log --oneline <коммит старта>..origin/main -- <папки>`) — `live.py`, поправить «как есть» мелкими находками в `main` и влить `main` в ветку. Решения — пунктами с якорями в требованиях; `(открыто)`, задевающее описание, — сначала вопрос решающему.

3. **Кого задевает:**
   ```bash
   python architecture/tools/find.py --service <сервис>
   python architecture/tools/find.py --process <процесс>
   python architecture/tools/find.py --code <путь[:строка]>
   python architecture/tools/find.py --chain '<сервис>: <ключ>'
   ```
   Команда даёт кандидатов, решает описывающий. Порядок — от основания графа. Копия — только md, чьё содержимое меняется; процесс, у которого меняется лишь то, что подтягивает генератор, — строкой в «Последствиях»; сомневаешься — строка; и копия среза, и строка о том же процессе вместе — ошибка проверки. Устаревший сервис копий не получает: его поломка — проблема без починки, судьба на обложке. Задетое командой, но не меняющееся, — в «Не задеты» с причиной. **Уведомить решающего и сразу работать, без вопроса:** сервисы и процессы, последствия, «не задеты», блоки, кто пишет и цена агентов; остановиться, только если объём вышел за согласованное — это развилка. Маленькая доработка — объём строкой в показе. Перед каждым заходом и после сжатия — строка «кто делает до ближайших ворот»: «сам — …; агенты — … (цена)».

4. **Читать задетое целиком:** README, срезы, `own.md`, файлы процессов — по числу строк, сходится с `wc -l`; справочник — `find.py '<ключ>'`; код, который будет меняться. Устарело по смыслу — сначала мелкая находка. Проверка: могу назвать ключи, которые трону, точно как в заголовках, и решение, на котором стоит каждая правка.

5. **Границы, хранилища, числа, открытые вопросы — до описания:** по [boundaries.md](boundaries.md). Вопрос решающему одним заходом: картинка потока 5–8 строк и AskUserQuestion, 3–4 вопроса, у варианта цена, рекомендуемый первым; границы механизма — `multiSelect`, «что берём сейчас?»; слова — для человека. Вопросов нет — шаг пропускается.

6. **Решения в требования и на обложку:** каждый ответ, задающий устройство, — пункт к своему объекту с пометкой, словами решающего и якорем `{#d-…}`, на обложке строка `- [[d-…]] — сжато` (`.claude/skills/backlog/format.md`). Было `(открыто)` — пометка снята, в пункте его слова; «на твоё усмотрение» — тоже с его словами. Своё предложение — `(не согласовано)`: оно сразу вопрос к решающему.

7. **Основание графа — первым:** договор, который зовут или читают другие (метод, событие, таблица), основная сессия пишет сама. До этого — одно сообщение: какие копии, кого задевает, какие блоки; что `TOBE/` — копии «как есть» с правками. Страницу для показа — `python architecture/tools/build.py architecture/TOBE/README.md`, открыть `python architecture/tools/open.py architecture/TOBE/<сервис>/index.html`, «предложено» — вопросом в тексте. Ответа не ждать, если его не требует развилка. Ошибка «не входит ни в одну задачу» до шага 12 ожидаема.

8. **Правки** — по [writing.md](writing.md):
   - уходящее — командой до агентов: `python architecture/tools/map.py gone --from "$S/gone.txt"`, строка «<номер> <решения> <md>[#раздел|раздел…]», список по `find.py --chain` и `--code`;
   - копия — `python architecture/tools/map.py tobe ASIS/<сервис>/<файл>.md`, правки блоками `:::` на месте, вне блоков байт в байт;
   - кто пишет: один-два сервиса — основная сессия; больше — агенты параллельно, по объёму (`PROCESS.md`, 8.1–8.2), бриф — копия [templates/brief-service.md](templates/brief-service.md). Обложку, `blocks.md`, `board.yaml` — основная сессия; процессы — она же или по агенту на процесс или пару. Стыки — ссылками на ключи, а не пересылкой текста.

9. **Задачи, тесты, удаляемый код, последствия:** заготовка `python architecture/tools/map.py blank tasks <сервис>`; что писать — [tasks-rules.md](tasks-rules.md). На обложке — «Судьбы проблем» и «Последствия для процессов» строкой: что теперь увидит человек. Документы репо — задачей блока; соседнего — строкой в `## После блоков`.

10. **Доска:** `python architecture/tools/map.py blank board`, поля — шапка файла. Только узлы изменения: `changes` — у вызывающего появился или ушёл подраздел «Связей», хранилище, подключение; у вызываемого — линия к нему; `new` — с местом и подписями по-русски; `gone` — с `why`; `open` — с вопросом. Чужих судеб не ставить.

11. **Блоки:** `python architecture/tools/map.py blank blocks`; как нарезать и строить волны — [blocks-rules.md](blocks-rules.md).

12. **Сведение и проверки:** строки ответов агентов: «для <сервиса>» — агенту, если работает (SendMessage), иначе сама; «ждёт пары» — разрыв между файлами, закрывает основная сессия; стыки — `find.py --process <процесс> --tobe`.
    ```bash
    python architecture/tools/build.py --check                 # 0 ошибок, только md; одна сборка на заход
    python architecture/tools/find.py --list правка --tobe     # все правки на числах, не по слову «ОК»
    python architecture/tools/where.py --gate ready            # закрыт только вопросами — нормально до показа; ошибками — чинить
    ```

13. **Полнота** — обе стороны, явно: по [completeness.md](completeness.md), начиная с `python architecture/tools/devCoverage.py`. Итог решающему числами. Маленькая доработка — шаг пропускается; решающий принял всё на старте и сказал работать автономно — тоже.

14. **Глазами** (у маленькой доработки страницы открываются на показе, снимков нет): страницы «как будет» один раз — `python architecture/tools/build.py architecture/TOBE/README.md`. Снимки: `python architecture/tools/devShot.py --map TOBE/index.html --out "$S/shots"`, так же доска `TOBE/01_service-map.html`, сервисы и процессы. Консоль без ошибок, кроме `favicon.ico`. Смотреть: на доске ярко только узлы изменения, подписи по-русски; правки видны — новое, меняется с «было», уходит; блоки все.

15. **Коммит описания:** один на старт и описание: `git add architecture/ _backlog/ CHANGELOG.md`, только свои пути; `docs(architecture): описание «<название>»` в ветку. От него `done.py` считает дифф, его номер — в `Описание утверждено:`. Правки по новичкам и ответу до «да» — `git commit --amend`, ветка не отправлена.

16. **Новички-исполнители:** обязательно (кроме маленьких доработок, которые делает основная сессия); прямое слово решающего «без новичков» действует всегда. По агенту на блок, `general-purpose`, в фоне, параллельно, бриф — копия [templates/brief-novice.md](templates/brief-novice.md); цена около 90–150 тыс. токенов на блок — строкой решающему. До запуска записать свои ответы на вопросы 2, 3, 6, 7, потом сверить. Находки — решающему сразу, одной-двумя строками; правки одним заходом: дыра — правкой «как будет» (шаги 8–15), неясное обозначение — в `architecture/CLAUDE.md`, противоречие — в `architecture/STANDARD.md`. Второго захода нет.

17. **Показ:** по образцу [templates/show.md](templates/show.md), начать с «это план, кода ещё нет». Страницы — `python architecture/tools/open.py architecture/TOBE/index.html`, словами что смотреть. Каждое `предложено` — своим разделом: ситуация примером с экрана, что решено, что предлагаю и почему, как иначе, цена, служебное слово объяснить; ответ — словами по номерам. В конце таблица волн и один вопрос «Начинаем волнами?». Блокирующие ворота: без «да» к коду нельзя. Маленькая доработка — показ без вопроса, «да» — слова со старта, сразу шаг 19; работу соседа — сообщением его сессии самой.

18. **Правки по ответу:** вопрос решающего — сначала ответить фактами; меняет устройство — решение, затем правки. Урезал объём — всё сразу: копии, процессы, доску, задачи, блоки. После правок — шаги 12, 14, 15; повторный показ — только изменившееся.

19. **«Да»:** `python architecture/tools/where.py --gate ready` — открыты; закрыты — назвать, что держит. На обложке под `Ветка:`: `Описание утверждено: <дата> · <коммит шага 15> · «<его слова>»`. Отдельного коммита нет: уходит с первым блоком. `where.py --gate approved` — открыты.

20. **Путеводитель, журнал, переход:** `python architecture/tools/devChangelog.py --now "Б1" --next "<что за ним>" --log "«да» решающего: <слова>"`. Что-то пошло не так — журнал, заголовок `### Описание: <изменение> · <дата>`. Дальше — `/dev-block b1`; вызван из `/dev` — вернуть управление.

**По ходу всех шагов:** решающий поправил ход, шаг не сработал или чего-то не хватило — запись в `architecture/JOURNAL.md` (вид — `architecture/PROCESS.md`, раздел 10); скилл, документы, шаблоны и скрипты процесса эта сессия не правит: не хватает инструмента — простейший обход во временной папке или вопрос решающему.

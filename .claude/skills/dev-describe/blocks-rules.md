# /dev-describe: как нарезать блоки и волны

Зачем: правила `blocks.md`. Кто читает: `/dev-describe`, шаг 11. Формат — `architecture/STANDARD.md`, 7.8. Блок — законченный кусок: его задачи, тесты, проверяемое «Готово, когда»; делает один агент.

1. Первым — задачи без зависимостей, дающие основу; дальше слоями снизу вверх: окружение, хранение и исполнитель, методы и удаление старого, проверка вживую. Один блок — один слой, 1–3 задачи, которые друг без друга не проверить. Порядок — ещё и по данным, которые нужны живой проверке.
2. Задачи двух репо в одном блоке — сказать в тексте, кто делает стык.
3. «Готово, когда» — только проверяемое: тесты интерфейса — весь набор `npx vitest run`, а не папка компонента; тесты `[[t-…]]` зелёные; что отвечает живой сервис; что в базе; что на экране; числа сверки. По роду блока обязательно: схема базы меняется — «контейнер перезапущен, версия миграции, чистый старт»; описание обещает остановку или перезапуск — «проверено вживую»; формат хранения меняется — «старые данные пересчитаны»; сверка «точно» — в том же окружении, что считало.
4. Живое состояние — правилом, а не числом снимка. Не опирать «готово» на запуск, который может ответить «нечего делать». Числа «до» — прогоном.
5. Проверка вживую не задевает того, что решающий запретил трогать, и не нажимает кнопки, запускающие тяжёлую работу.
6. Последний блок — проверка вживую на настоящих данных. «Как есть» заново — не блок: это закрытие. Проверка, которой надо ждать (ночь, расписание, чужая работа), — не блок: новая задача `python architecture/tools/backlog.py new <тема>-check "<название>"`, в её папке `CHECK.md` — копия `.claude/skills/dev-describe/templates/check.md`.
7. Волны (`PROCESS.md`, 8.4): граф блоков по `После:` и по файлам. В волну — все блоки, у которых сделаны блоки из `После:` и нет общих файлов (расписание, точка сборки, одна страница). Зависимость «по договору» не держит: договор записан в «как будет», код пишется с подменами, ждёт только живая проверка. Перед показом — пересчёт: у каждого «После:» назвать общий файл или код, без которого блок не собрать; нет — убрать. Блоки, которые правят одни файлы (compose, роутер), — слить; чистую библиотеку — отдельной папкой параллельно с каркасом.

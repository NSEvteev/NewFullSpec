# /dev-describe: показ решающему

Зачем: как показать описание, чтобы решающий понял и решил. Кто читает: `/dev-describe`, шаг 17. Начать с фразы «это план, кода ещё нет»; файлы, удаляемый код, итоги проверок — одной строкой или по просьбе. Страницы открыть и словами сказать, что на них смотреть.

```
Это план, кода ещё нет. Что меняем: <одна фраза>. Что увидит человек после изменения:
<3–5 строк>

Страницы «как будет» (открыл): обложка — решения, что не задето, судьбы проблем; доска — ярко только это изменение; <сервис> — <что смотреть>; процесс «<название>» — <что смотреть>.

Границы (по твоим ответам): берём …; не берём … — <что это значит на деле>.
Что удаляем из кода: <по смыслу> — выключенное удаляем сразу, чтобы карта не врала.
Кого задевает без копий: <процесс> — <что теперь увидит человек>.
Мои предложения — ответь по номерам (каждое — своим разделом: ситуация примером с экрана, что решено, что предлагаю и почему, как иначе, цена): 1) … 2) …
Блоки: Б1 <название> — готово, когда <по-человечески>; Б2 …; последний — проверка вживую на <чём>.
Волны: 1 — Б1, Б2, Б4 (разные сервисы, договор записан); 2 — Б3 (ждёт таблицу Б1); 3 — проверка вживую.
Новички по блокам: нашли <что>, поправлено <что>.
Открытые вопросы: нет / <вопрос>.

Начинаем волнами?
```

Блок один — «Начинаем Б1?». Маленькая доработка — показ без вопроса: `/dev-describe`, шаг 17.

# /dev-start — старт: задача и решения до описания

Ведёт от названной задачи до решённых развилок: решения — в требованиях и строками на обложке. Код и «как будет» здесь не пишутся. Между остановками работать самому; вопросы решающему — только для развилок. Команды — из корня репо, в Bash. Задача — одно конкретное действие («поправь», «посчитай», «покажи») — сделать ровно его и остановиться; правка «как есть» без кода — мелкая находка (`PROCESS.md`, раздел 1). `where.py` показывает старт с `(открыто)` в требованиях — продолжать с шага 7.

1. **Прочитать:** всё, что печатает `python architecture/tools/where.py --read dev-start`; новая сессия — ещё `--read dev`. Неразобранные записи журнала — знать о них; разбирает сессия разбора (`PROCESS.md`, раздел 12).

2. **Ворота старта** — без вопросов:
   ```bash
   python architecture/tools/where.py --gate start
   ```
   Сервисы — командой из `PROJECT.md`; соседние репо — их незакоммиченное (чужая работа: не коммитить, не откатывать). Закрыто — по таблице:

   | Что | Что делать |
   |---|---|
   | идёт другой шаг; стою на `change/…` | вернуться в `/dev` |
   | стою на чужой ветке | сказать решающему и спросить, переходить ли на `main`; не переключать молча |
   | не отправлено | назвать коммиты и спросить: отправить сейчас? Иначе уедут в PR и склеятся при squash |
   | не забрано | сказать решающему; `git pull --ff-only`, если незакоммиченное не в тех же файлах |
   | незакоммичено чужое | не трогать, назвать в «где мы» |
   | сервисы нездоровы | поднять по `PROJECT.md`, чинить в этой сессии; нельзя по причине вне сессии — `--gate start --no-facts` и строка решающему: факты не сверены |
   | строка кода сдвинулась, текст тот же | `python architecture/tools/relocate.py --dry-run`, затем без него |
   | строка изменилась по смыслу; факты разошлись с md | поправить md по коду — мелкая находка: md, `build.py`, коммит в `main`, push |
   | ошибки от коммитов соседнего репо | отделить от своих; вопрос решающему: чинить сейчас или на старте следующего |

   Механическое — сразу и строкой в «где мы». Описание врёт во многих местах — назвать масштаб и чинить: поверх ложной карты не начинать. Итог — 0 ошибок.

3. **Где мы** — простым языком, по смыслу: последнее законченное изменение и чем кончилось (`git log --oneline -5 origin/main`); задача и чего она касается по обзору `architecture/ASIS/README.md` — как предположение, задачи нет — спросить «что меняем?»; окружение: сервисы, карта, git; следующий шаг одной фразой. **Стоп:** на холодном старте только пересказ.

4. **Чтение задетого:**
   - задача есть в бэклоге — `python architecture/tools/backlog.py status <тема>`, её промт и папку целиком: согласованное не спрашивать, `(открыто)` и `(не согласовано)` — в развилки шага 7;
   - вход — то, что трогает человек: `python architecture/tools/find.py '<сервис>: <ключ страницы или метода>'`; в ответе задетые процессы и шаги. Процесс по названию не угадывать;
   - `find.py --service <сервис>`, `--process <процесс>` по каждому найденному; README, файлы процессов и срезы — целиком, справочник — по ключу;
   - ответ уже в карте? `find.py --text <слово>`, по одному слову основой и по значениям из кода. Вопрос с ответом в карте — не развилка, а умолчание со ссылкой;
   - код — где без него непонятно, по ссылкам `путь:строка`; материалы соседнего репо — если изменение из них растёт;
   - задача пришла планом соседней сессии — до пересказа прочитать её материалы и сверить понимание с автором (`ListAgents`, затем SendMessage): пересказ соседа — не слова решающего.

5. **Пересказ задачи и порядок.** Своими словами: что хотим получить по смыслу для человека; как строится из того, что есть; состав — сервисы и процессы, границы как их называет решающий, не дробить, начинать с основания графа; что перестанет работать как факт перехода, а внутренние шаги перехода — умолчанием; что уходит — словами экрана и рядом что остаётся, имена кода только после; слабые места прямо, с доводом; решающий сам описывает устройство — таблицей «было, станет»; умолчания списком с просьбой поправить. Порядок развилок: почему здесь и от чего зависит (рамка, что считаем, как храним, кто считает). **Стоп:** «да?» простым текстом; поправки принять и пересказать изменённое одной фразой. «Да» на умолчания — не «да» на устройство и код.

6. **Факты под развилки.** Список: вопросы, без которых изменение не описать; границы — что входит сейчас, что позже; хранилище — кто пишет, кто и как читает каждый потребитель (`find.py --chain '<ключ>'`), как дописывается и что пересчитывается. Решение «из тестовой версии» — не решение. Развилка-вкус — без агента. Для фактов нужно читать код или данные сверх нескольких файлов — агенты по одному на развилку, параллельно, только чтение; два и более — цена строкой; бриф — копия [templates/brief-facts.md](templates/brief-facts.md). До запуска найти сделанные замеры: `find.py --text замер` и материалы соседа. Пока работают — готовить картинку потока. Отчёты проверить: по 2–3 ссылки и число, на котором держится рекомендация; без источника — проверить или выбросить; PARTIAL — дособрать или «не выяснено». Решающему отчёты не пересылать.

7. **Развилки** (решает решающий):
   - картинка потока в чате, блоком кода: кто, что, куда, от действия человека до результата; новое помечено, развилки — «[? …]»;
   - меняется вид страницы — [screens.md](../backlog/screens.md);
   - все развилки — одним сообщением при общей картинке. У каждой: вопрос о том, что решает решающий, на примере с экрана с 2–3 исходами; варианты: что значит на деле, цена, что закрывает, по всем потребителям, нынешним и названным в плане, а задержка, которая вышла только из устройства системы, — не вариант; рекомендация и почему, равноправны — так и сказать; что уже устроено, решено, предложено; у числа основание; развилка о данных — после своей проверки файлов, состояние — проверяемым правилом;
   - что следует из правил предметной области (`PROJECT.md`, «Как используется») — умолчанием с правилом и примером;
   - затем вопросы в чате, все сразу, с номерами 1, 2, 3…: по вопросу на развилку, 2–4 варианта, рекомендованный первым с «(рекомендую)», цена фразой; решающий отвечает в чате по номерам. Свободный ответ читается двояко — оба прочтения мини-схемой и вопрос; про интерфейс — буквальный смысл слов. Вопрос решающего в ответ часто и есть решение — записать сразу;
   - автономный режим (сказал работать автономно или требования оформлены с ним): развилку с ясной рекомендацией решить пунктом `- (по рекомендации) **<решение>** {#d-<смысл>} (<дата>): <что и почему>; цена: …; отвергнуто: …`, это исключение из правила пометок (`PROCESS.md`, 6.4); вопрос — только если варианты равноценны и меняют видимое человеку;
   - откладывает — спросить, задевает ли изменение: задевает — описывать нельзя, пункт `(открыто)`; нет — назвать отложенной и завести задачу: `python architecture/tools/backlog.py new <тема> "<название>" --tobe <тема изменения>`; в набор не ставить. Выход — развилок, задевающих изменение, нет.

8. **Ветка, обложка, требования.** `main` = `origin/main`. Размер — маленькая доработка (по оценке один сервис, до двух блоков, или слово решающего «делай сам»; `PROCESS.md`, раздел 1) — с `--small`:
   ```bash
   python architecture/tools/map.py start <имя латиницей> "<название словами решающего>" <тема> [--small]
   ```
   Команда завела `change/<имя>` и обложку; требования — задача бэклога `_backlog/promt-<тема>.md` с папкой: есть такая тема — та же задача, нет — новая. Большой набор — файлами по частям в папке задачи. Через Edit:
   - промт: по объектам, слова решающего, факты `путь:строка`, макеты; решение — пунктом к своему объекту, формат и пометки — `.claude/skills/backlog/format.md`, пример — `architecture/tools/samples/good/_backlog/promt-payment-retry.md`. Пункт, на котором будет стоять описание, — с якорем `{#d-<смысл>}`. Ответ пришёл — пометка и текст по ответу, отвергнутое убрать, якорь оставить. Требования к экрану — своим разделом, только его словами, предложения отдельно;
   - обложка: что меняем и зачем 2–4 фразы; под `## Решения` — строка `- [[d-<смысл>]] — сжато` без статуса; последствия, «Не задеты», судьбы проблем пишет описание;
   - решение меняет порядок работы, а не устройство, — ещё и память Claude.

   `python architecture/tools/build.py --check` — код 0; `where.py` — название и ▶ описание, или ▶ старт с вопросом. Коммита нет: всё уходит одним коммитом с описанием.

9. **Итог и переход.** `python architecture/tools/devChangelog.py --now "описание" --next "показ и «да»" --log "старт: решения по <…>"`; вопрос ждёт — ещё `--wait "<вопрос>"`. Решающему: решения по смыслу и что они меняют; что отложено и почему не мешает; что сделано с картой; дальше описание, до кода будет показ и «да» (у маленькой доработки «да» — его слова со старта: их и записать на обложку); отдельного вопроса «описывать?» нет. Что-то пошло не так — журнал, заголовок `### Старт: <изменение> · <дата>`. Вызван из `/dev` — вернуть управление; напрямую — `/dev-describe`.

**По ходу всех шагов:** решающий поправил ход, шаг не сработал или чего-то не хватило — запись в `architecture/JOURNAL.md` (вид — `architecture/PROCESS.md`, раздел 10); скилл, документы, шаблоны и скрипты процесса эта сессия не правит: не хватает инструмента — простейший обход во временной папке или вопрос решающему.

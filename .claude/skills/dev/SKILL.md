# /dev — ведущий процесса изменений

Сам ничего не строит, не пишет код, не собирает карту и не запускает агентов. Аргументы: `статус` — только показать, без вопросов и запуска; `до конца` (и слова «делай всё до конца», «работай автономно») — то же, что без аргумента: шаг за шагом до ворот решающего; текст — задача словами, передаётся в `/dev-start`. Не для: мелкой находки в «как есть» (`PROCESS.md`, раздел 1), вопроса «как устроено» (`find.py`), работы со своим порядком в соседнем репо. Команды — из корня репо, в Bash.

1. **Прочитать** — только в новой сессии: всё, что печатает `python architecture/tools/where.py --read dev`. `python architecture/tools/kit.py status` с кодом 1 — проект из шаблона не настроен: сначала `/new-project`. Проверка: могу назвать три правила разговора с решающим и сказать, идёт ли изменение.

2. **Где мы** — одной командой, ветки не переключать: блоки команда читает из ветки изменения сама, а живые сервисы берут код с диска.
   ```bash
   python architecture/tools/where.py --guide
   ```
   Прочитать все строки; за предупреждением идёт строка «что делать», а строку «Читать к шагу» исполняет сам шаг. Код 2 — ошибка состояния, идти дальше нельзя: в `TOBE/` есть файлы, а обложки нет — показать и спросить, недоделанный старт или остаток закрытия; другая причина — разобрать по сообщению. «Неслитая работа» без обложки — показать вывод и спросить; не угадывать. При `статус` — только назвать в показе.

3. **Путеводитель:** `python architecture/tools/devChangelog.py --now "<что запускаю>" --next "<что за ним>"` собирает шаги из файлов. В «Ход работы» записано «утверждено», а на обложке нет `Описание утверждено:` или блок готов без `Сделано:` — спросить решающего одной строкой, не править молча. При `статус` — файл не трогать, расхождение только назвать.

4. **Выбрать шаг** — строка «Дальше:». Поправки по разговору, только эти:
   - изменения нет, задача названа — `/dev-start <задача>`; не названа — показать список `python architecture/tools/backlog.py` и спросить, что брать. Задача ведётся не этим процессом (другой репо) — не стартовать, назвать, где она ведётся;
   - решающий прямо назвал шаг — проверить: «начинаем», «делай Б4» — `where.py --gate approved`, а блоки из `После:` проверит сам `/dev-block`; «мержи» — `where.py --gate blocks-done`; «закрывай» — `where.py` показывает шаг «закрытие». Можно — запустить; нельзя — причина из вывода и верный шаг;
   - новая задача при идущем изменении: часть текущего — `/dev-describe дописать`; нет — возьмём после закрытия, продолжить текущее. Вторую обложку не заводить;
   - нужен код, которого нет в «как будет» (ревью, закрытие), — `/dev-describe дописать`, потом `/dev-block`. Исключение — исправления по ревью с готовым списком: код сразу, описание рядом (`/dev-deliver`, шаг 7).

5. **Ворота:** строка «Слово» вывода. Нужно и нет — один вопрос. Код — только после «да» на описание: «да» на решение — не «да» на код. «Да» лежит на обложке; слово сказано в этой сессии, а поля нет — его записывает `/dev-describe`. Показ был в прошлой сессии, а слова нет — AskUserQuestion: «Описание изменения «<название>» готово: <N> сервисов, <M> процессов, <K> блоков в <W> волнах. Начинаем код волнами?» — «Начинаем волнами (рекомендую)» · «Сначала покажи описание» · «Поправить описание»; числа: блоки — строка «Блоки:», сервисы — папки в `architecture/TOBE/` кроме `_processes`, процессы — файлы в `architecture/TOBE/_processes/`, волны — по `После:` блоков; ответ ведёт в `/dev-describe`. «Продолжать?» между блоками не спрашивать.

6. **Показать** — числа из вывода и шага 5, что даст блок — из `find.py b<N> --tobe`, по смыслу, без имён полей и кодов проверок:
   ```
   Где мы: идёт изменение «<название>». Описание утверждено, код идёт:
   готовы 2 блока из 5. Дальше Б3 «<блок>» — после него <что это даст человеку>.
   Мешает: ничего.

   ✅ 1. Старт — решения приняты
   ✅ 2. Описание — 3 сервиса, 2 процесса, 5 блоков; «да» получено
   ▶ 3. Блоки — Б1 ✅ · Б2 ✅ · Б3 ▶ · Б4 ⬜ · Б5 ⬜
   ⬜ 4. Доставка — ревью, PR, merge
   ⬜ 5. Закрытие — «как есть» заново, «как будет» пусто

   Запускаю /dev-block b3.
   ```
   Шаги — в `CHANGELOG.md` и в чате, не инструментом задач. При `статус` вместо «Запускаю» — «Следующий шаг: …, не запускаю», и на этом стоп.

7. **Запустить** инструментом Skill: `dev-start` (задача словами), `dev-describe`, `dev-block` (аргумент `b3`), `dev-deliver`, `dev-close`. Дальше — строго по запущенному скиллу.

8. **После шага:** снова `where.py`. Выход должен быть виден в файлах: старт — обложка; описание — `Описание утверждено:`, шаг «блок»; блок — его `Сделано:`; доставка — шаг «закрытие»; закрытие — «Изменения нет». Сказал «готово», а не видно — вернуться в шаг: отчёт агента не доказательство. `python architecture/tools/devChangelog.py`, шаги в чате. Без ворот — сразу следующий шаг; решающий сказал «по одному шагу» или «стоп» — остановиться. «Изменения нет» — сказать «изменение закрыто» и остановиться: новое только словом решающего.

**По ходу всех шагов:** шаг выбран неверно, решающий поправил порядок, нашлось противоречие в состоянии или чего-то не хватило — запись в `architecture/JOURNAL.md` (вид — `architecture/PROCESS.md`, раздел 10); скилл, документы, шаблоны и скрипты процесса эта сессия не правит: не хватает инструмента — простейший обход во временной папке или вопрос решающему.

# /docker-up — поднять окружение

Compose-файл и файл переменных — ключ `compose` в `architecture/project/settings.yaml` (`file`, `env`); ниже они названы `<file>` и `<env>`. Ключа нет — проект без compose: сказать одной строкой и остановиться. Compose-файл — это и есть список сервисов, портов и томов. Значения секретов не выводить.

1. **Прочитать вывод:** `docker compose -f <file> ps --format '{{.Name}} {{.Status}}'`. Все `healthy` — ничего не делать, сказать одной строкой.

2. **Предусловия:** Docker запущен (`docker ps` без ошибки); `<env>` есть (нет — скопировать из `.env.example` рядом, секреты заполняет решающий); в `<env>` есть каждая переменная, которую compose требует видом `${ИМЯ:?…}`, — например, пароль базы `POSTGRES_PASSWORD`: проверка — `docker compose -f <file> config --quiet` без ошибки, недостающее дописать из `.env.example`; `.dockerignore` в корне репо есть.

3. **Поднять:** `docker compose -f <file> up -d` — без `--build`, если зависимости не менялись: сборка всех образов идёт минуты. Менялись зависимости или Dockerfile сервиса — `up -d --build <сервис>`.

4. **Здоровье:** снова `docker compose -f <file> ps` — у каждого контейнера из compose-файла `healthy`, у баз тоже; сервис, который ждёт базу (`depends_on` с `service_healthy`), стартует только после неё, поэтому нездоровая база держит и его — чинить сначала базу. Адрес проверки здоровья сервисов — `PROJECT.md`, «Команды». Нездоровый — `docker compose -f <file> logs --tail 60 <сервис>` и таблица:

   | Симптом | Причина | Что делать |
   |---------|---------|------------|
   | `bind: address already in use` | запущен другой compose или процесс на порту | `docker ps`, остановить мешающее |
   | `required variable … is missing a value` | в `<env>` нет переменной, которую требует compose | дописать её из `.env.example` |
   | сервис с базой: `password authentication failed` | пароль в `<env>` сменили после первого старта базы, а база хранит пароль из тома | вернуть прежний пароль в `<env>`; сменить — в самой базе, том не стирать |
   | сборка висит больше 5 минут | нет `.dockerignore` или широкий контекст сборки | проверить `.dockerignore` |
   | сервис нездоров: ошибка разбора `.env` | `pydantic-settings` читает `list[str]` как JSON | значение — `["a","b"]`, не `a,b` |
   | сервис не видит общий пакет | нет тома с пакетом или `PYTHONPATH` | добавить в compose, как у соседних сервисов |
   | интерфейс падает с `EIO` на томе | Vite без опроса файлов на Windows | не выключать `usePolling` в конфиге Vite |
   | сервис упал сразу после правки кода | перезапуск подхватил код раньше миграции базы | применить миграцию, перезапустить контейнер |
   | `docker stop` ждёт 10 с и убивает | команда запуска без `exec`, первым процессом — `sh` | `exec <команда>` в compose |

5. **Итог решающему** — одной-двумя строками: сколько здоровы, что чинил. Остановить: `docker compose -f <file> stop`, контейнеры сохраняются; `down -v` стирает тома — данные баз и загруженные файлы — только по слову решающего.

**По ходу всех шагов:** шаг не сработал или чего-то не хватило — запись в `architecture/JOURNAL.md` (вид — `architecture/PROCESS.md`, раздел 10); скилл эта сессия не правит.

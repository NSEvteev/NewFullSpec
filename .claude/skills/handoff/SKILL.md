# /handoff — передача следующей сессии перед сжатием

Монитор контекста общий для машины — `~/.claude/ctxmon/`, как он работает — его `README.md`; на машине его нет — сказать решающему, что монитор ставится по `.claude/ctxmon/INSTALL.md`, и остановиться. Сжимает решающий, своим словом, и передачу сессия пишет по его просьбе. После любого сжатия монитор подкладывает передачу и сам будит сессию: она читает файлы «Прочитать целиком» и продолжает с первого шага передачи. Команды — из корня репо, в Bash: проверка ищет файлы «Прочитать целиком» от текущей папки.

1. **Прочитать передачу — сначала создать её:** копия шаблона монитора с машинной частью — слова решающего дословно, вызванные скиллы, правленые файлы, номер сессии. Команда печатает путь передачи и строку `/compact`:
   ```bash
   PYTHONIOENCODING=utf-8 python ~/.claude/ctxmon/ctxHandoff.py --session "$CLAUDE_CODE_SESSION_ID"
   ```
   Затем Read по напечатанному пути: подсказки у каждого раздела говорят, что в нём писать.

2. **Где мы** — вывод команды своей работы, дословно, блоком кода, а под ним строкой — какой скилл и с какого его шага продолжать:
   - изменение системы (`/dev*`) — `python architecture/tools/where.py`. Блок, агент ещё работает — ждать его отчёт (имя агента), затем `/dev-block b<N>` с разбора отчёта: брифа заново не писать, второго агента не запускать. Закрытие — ещё признаки из `.claude/skills/dev-close/resume.md`, какие уже есть;
   - задача бэклога (`/backlog`) — `python architecture/tools/backlog.py status <номер или тема>`;
   - настройка проекта (`/new-project`) — `python architecture/tools/kit.py status`;
   - мелкая находка, разбор журнала, другая работа без своей команды — `git status -sb` и что правится в каком файле.

3. **Прочитать целиком** — по файлу на строку, путь от корня репо или полный; только то, без чего первый шаг после сжатия не сделать:
   - изменение — набор требований: поле `Требования:` обложки `TOBE/README.md`, промт `_backlog/promt-<тема>.md` и md его папки, без макетов html; у блока — ещё бриф агента полным путём (`$S/brief_<изменение>_b<N>.md`, `/dev-block`, шаг 7);
   - задача бэклога — её промт и md её папки;
   - иначе — документ, который пишется, и входы шага.

   Вывод `where.py --read` сюда не переписывать: входы шага `/dev*` после сжатия читает сам шаг, а строки этого вывода — не только файлы, и `--check` на них падает.

4. **Первый шаг** — в раздел «Что сейчас и первый шаг после сжатия»: идёт изменение — `/dev`; после сжатия сессия для него новая и читает всё по его шагу 1 (`architecture/PROCESS.md`, раздел 0.1). До первой правки — требования из шага 3 и слова решающего из записи разговора (там же, раздел 6.5): `python architecture/tools/devWords.py --session <номер>`. Номер сессии взять из машинной части и вписать в команду сейчас: после сжатия он может смениться. Задача бэклога — `/backlog <тема>`. Другая работа — команда или действие, с которого начать.

5. **Заполнить каждый раздел через Edit:** «…» — текстом, пустой раздел — словом «нет»; машинную часть не трогать.
   - «Решения … ещё не внесённые в файлы»: дословно, с временем и с местом, куда внести. Решение по изменению или задаче бэклога — сейчас пунктом в требования (`architecture/PROCESS.md`, раздел 6.4), в передаче — файл и пункт; пока агент блока коммитит, файлы репо не править — тогда только в передаче.
   - «Что ждём»: агенты блоков — имя, блок, рабочая копия и где бриф; сессии соседних репо (`PROJECT.md`, «Соседние репо») — о чём им писали и что ждём в ответ; PR и его проверки.
   - «Чего не делать»: то, за что решающий уже поправлял в этой работе; запреты шага, которые легко забыть, — со ссылкой на место, где они записаны.

6. **Проверить** — «передача заполнена»; проверка сама открывает передачу решающему в VS Code:
   ```bash
   PYTHONIOENCODING=utf-8 python ~/.claude/ctxmon/ctxHandoff.py --check <путь передачи>
   ```
   Затем вычитать передачу глазами новой сессии по четырём вопросам, которые печатает проверка. Чего-то нет — дописать через Edit и снова `--check`.

7. **Решающему в сообщении:** путь передачи; что показала вычитка, по каждому из четырёх вопросов; строку `/compact` из шага 1 целиком, блоком кода; что после сжатия монитор сам разбудит сессию и писать ей ничего не нужно.

**По ходу всех шагов:** о сжатии не спрашивать и его не предлагать — сообщения монитора адресованы решающему. В передаче — только то, чего после сжатия не восстановить из файлов, git и `where.py`. Скилл не сработал или решающий поправил передачу — запись в `architecture/JOURNAL.md`; скилл эта сессия не правит.

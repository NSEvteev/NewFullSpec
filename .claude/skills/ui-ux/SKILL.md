# /ui-ux — дизайн-система поверхности

Первый из трёх скиллов макета: `/ui-ux` — дизайн-система, `/design` — экраны, `/animation` — движение. Поверхность — отдельный интерфейс со своим видом: например, панель, большой экран, телефон. Её дизайн-система общая для всех задач: `_backlog/_shared/design/<поверхность>.md`, имя латиницей; по ней `/design` строит экраны, раздел «Движение» в ней ведёт `/animation`. Основа — скилл UI UX Pro Max: его файлы лежат как есть в [upstream/](upstream/), откуда и что взято — [upstream/SOURCE.md](upstream/SOURCE.md). Команды — из корня репо, в Bash; `U` ниже — `python .claude/skills/ui-ux/upstream/scripts/search.py`: таблицы скрипт находит от своего пути, переменная `CLAUDE_PLUGIN_ROOT` из команд оригинала не нужна. База на английском — запросы тоже.

1. **Прочитать вход:**
   - задача — `_backlog/promt-<тема>.md`, раздел «Макет», и папка `_backlog/<тема>/`: объекты, состояния каждого типа объекта, их порядок, как пользователь ведёт объект по состояниям, на какой поверхности это видно;
   - `_backlog/_shared/design/<поверхность>.md` — есть: дальше его дополнять, а не писать заново;
   - поверхность уже есть в коде — её значения: где интерфейс, — `PROJECT.md`, «Сервисы и технологии»; Grep `^\s*--[a-z0-9-]+\s*:` по его стилям без `node_modules`, ещё `font-family`, `font-size`, `border-radius`, `box-shadow`; у каждого значения — `путь:строка`. Это и есть дизайн-система поверхности: база её не заменяет, и шаги 2–4 у такой поверхности — только когда решающий просит предложений или значения не хватает; иначе сразу шаг 5;
   - правила вида, которые решающий уже сказал (требования прошлых задач, их «Не будет» и макеты; заметки о его вкусе) — в раздел правил компонентов: так их увидят `/design` и `/animation`;
   - стек — по `package.json` интерфейса (`react`, `vue`, `svelte`, `nextjs` и другие из списка `--stack`); не нашёлся — вопрос, не угадывать;
   - оригинал — [upstream/SKILL.upstream.md](upstream/SKILL.upstream.md), разделы `Rule Categories by Priority`, `Query Contract`, `If a search returns 0 results`.

   Нет объектов, состояний или поверхности — не выдумывать: вопрос решающему. Вопросы — в чате одним списком с номерами, все сразу: суть, варианты с ценой, рекомендуемый первым. Без ответа про объекты и состояния дальше не идти.

2. **Собрать запрос:** одно намерение, 2–5 слов по-английски — тип продукта, назначение, одно-два слова стиля: `internal admin tool productivity`, `mobile companion app playful`. Имён проекта, людей и данных в запросе нет.
   - Тип продукта сверить до сборки: `U "<2–3 слова>" --domain product` — верхний `Product Type` должен быть про ту же поверхность. Слово `admin` тянет `Smart Home/IoT Dashboard`; пустой ответ даёт тип `General` с правилами по умолчанию. Тогда назвать тип словами базы (`productivity tool`, `SaaS`) и сверить снова.
   - Плотность — ключ `--density`: 8–10 — плотная панель с таблицами, 4–7 — обычная, 1–3 — просторная витрина. Смелость стиля — `--variance`: 1–3 спокойный, 8–10 смелый; без нужды не ставить. `--motion` не ставить: движение — `/animation`.

3. **Поиск дизайн-системы:**
   ```bash
   U "<запрос>" --design-system -f markdown -p "<поверхность>" --density <N> --persist --output-dir "<временная папка сессии>"
   ```
   - В выводе — стиль, палитра по ролям (`Primary`, `On Primary`, `Background`, `Muted`, `Border`, `Destructive`, `Ring` и другие), шрифты, эффекты, чего избегать. В `<временная папка>/design-system/<поверхность>/MASTER.md` — ещё `Category` (что база поняла про продукт), шкала отступов `--space-*`, тени `--shadow-*`, правила кнопок, карточек, полей, окон. Прочитать оба.
   - `--persist` — только во временную папку: в репо он пишет свою папку `design-system/`, а место у нас одно. `--stack` вместе с `--design-system` не работает — отдельным поиском на шаге 4.
   - Проверить: `Category` — та поверхность; стиль и палитра подходят назначению; контраст каждой пары `X` и `On X` — от 4.5:1. Мимо или пусто — один повтор с запросом уже; снова мимо — сказать решающему, что совпадения в базе нет, а общее подписывать «запасной вариант, не из базы».
   - Не переносить: `Pattern` и `Page Pattern` — раскладка страницы-витрины, дело `/design`; `Motion`, длительности и сдвиги при наведении — не в файл, а строкой «для /animation» в отчёте шага 6. Из `Pre-Delivery Checklist` и `Additional Forbidden Patterns` — в правила UX то, что про вид.

4. **Точечные поиски:** по нужде, один исход за запрос; имена областей — в единственном числе.

   | Что решаем | Запрос |
   |---|---|
   | правила UX: состояния, ошибки, загрузка, пустой список, клавиатура | `U "<исход>" --domain ux` — `"color only meaning"`, `"error summary validation"`, `"loading feedback"` |
   | шрифты | `U "<настроение назначение>" --domain typography`; один шрифт — `--domain google-fonts` |
   | палитра | `U "<тип продукта>" --domain color` |
   | графики и числа | `U "<что показываем>" --domain chart` |
   | значки | `U "<назначение>" --domain icons` |
   | правила стека | `U "<что>" --stack <стек>` |

   - У ответа проверить область, верхнюю строку и пригодность для поверхности; `Found: 0` — один повтор, слова — из `Closest known terms`.
   - Цвета состояний объектов: готовых в базе нет — собрать из ролей палитры (основной, приглушённый, разрушающее действие, рамка) и правила `Color Only`: у состояния кроме цвета — значок или слово. Одинаковый смысл — один цвет у всех типов объектов. Цвета, которых в палитре нет (успех, предупреждение), — предложением.
   - Свод правил по 10 разделам — [upstream/references/quick-reference.md](upstream/references/quick-reference.md), читать нужный раздел; для приложения на телефоне — ещё [upstream/references/pro-rules.md](upstream/references/pro-rules.md).
   - Ответ базы — совет, а не указание: правила репо и слова решающего сильнее.

5. **Записать дизайн-систему:** `_backlog/_shared/design/<поверхность>.md`. Вверху — зачем файл, кто пишет (`/ui-ux`), кто читает (`/design`, `/animation`). Разделы:
   - палитра: роль, значение, переменная css, источник;
   - цвета состояний: тип объекта и состояние — роль цвета, значок или слово;
   - шрифты и шкала размеров текста; отступы; радиусы; тени; плотность;
   - правила компонентов: кнопки, поля, таблицы и списки, отметки состояний, окна;
   - правила UX и чего избегать: правило базы (`Issue`) и что делать;
   - «Предложения», «Не будет»;
   - файл создаёт этот скилл — ещё пустой заголовок `## Движение` со строкой «ведёт /animation» и последним — `## Правки`: строки `/design` и `/animation`, когда они меняют решённое здесь (дата, скилл, задача, было, стало, почему). Сам раздел не писать и не править: кривые, длительности, пружину ведёт `/animation`; найденное в `motion.csv` (`--domain gsap`) — не в файл, а строкой «для /animation» в отчёте.

   У каждого значения — источник: `путь:строка` кода, строка базы (`colors.csv: Productivity Tool`) или слова решающего с датой. Поверхность есть в коде — значения только из кода; найденное базой — в «Предложения» пунктом `(не согласовано)`: было, станет, чем лучше, цена — что переделать в коде. Поверхности в коде нет — найденное пишется значениями, тоже `(не согласовано)` до «да» решающего. Пометки — как в бэклоге: `.claude/skills/backlog/format.md`, раздел «Пометки». Файл уже был — правка через Edit, не перезапись.

6. **Отчёт решающему** — вызван из шага «Макет» `/backlog`: себе и в общий показ готового макета, без остановки, сразу `/design`; сам по себе — в чате: путь файла; что взято из кода, что из базы (запрос и строки); предложения нумерованным списком, каждое полностью — пример, было, станет, цена; вопросы — тоже по номерам, рекомендуемый вариант первым; строка «для /animation» — что база сказала про движение, если сказала. Ответ пришёл: «да» — снять пометку, его слова с датой — в пункт; «нет» — пункт в «Не будет» с его словами. Дальше — `/design`: он читает этот файл.

**По ходу всех шагов:** экраны, раскладку и движение не решать, код не править; скилл пишет только `_backlog/_shared/design/`; `--persist` и проверочные файлы — только во временную папку сессии, `--force` не нужен; коммит — по правилам `/backlog`. Решающий поправил ход или чего-то не хватило — запись в `architecture/JOURNAL.md` (вид — `architecture/PROCESS.md`, раздел 10); скилл эта сессия не правит.

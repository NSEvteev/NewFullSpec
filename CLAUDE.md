**Где мы в идущем изменении — [CHANGELOG.md](/CHANGELOG.md)** (шаг, блок, задача, «сейчас» и «дальше»; ведётся на каждом шаге `/dev`). **Бэклог** — все задачи и требования к ним — [_backlog/CLAUDE.md](/_backlog/CLAUDE.md), скилл `/backlog`; порядка работ нет, что брать дальше, выбирает решающий. **Проектное** (команды проверок, вход для проверок, правила предметной области, соседние репо) — [PROJECT.md](/PROJECT.md).

**Правила:** подгружаются сами из `/.claude/rules/` при работе с файлами. Стандарт кода — [architecture/standards/code.md](/architecture/standards/code.md). Как устроен сам набор и как переносить его улучшения — [architecture/KIT.md](/architecture/KIT.md).

## Команды

```bash
make setup     # Установить зависимости инструментов и pre-commit хуки (ОБЯЗАТЕЛЬНО после клонирования!)
make init      # setup + метки GitHub + прогон всех хуков
make help      # Показать все команды
make dev       # Запустить для разработки (docker compose); проверить и починить — /docker-up
make stop      # Остановить сервисы
make test      # Тесты инструментов карты и пакетов
make lint      # Линтинг
make clean     # Очистка (docker down -v — стирает данные баз)
```

## Устройство

| Папка | Назначение |
|-------|------------|
| `/src/{service}/` | Код сервиса (сам код, база, тесты) |
| `/shared/` | Общие пакеты сервисов |
| `/platform/` | Запуск: Docker, шлюз, мониторинг |
| `/config/` | Конфигурации окружений |
| `/architecture/` | Карта «как есть» и «как будет», процесс изменений, стандарт кода, журнал |
| `/_backlog/` | Бэклог: задачи и требования к ним, макеты; сделанная задача удаляется |
| `/scripts/` | Скрипты для проверок (`test_limited.py` — тесты с потолком памяти) |
| `/.claude/` | Скиллы (`/new-project`, `/dev`, `/backlog`, `/docker-up`), правила |

Раскладка кода — умолчание: другой проект может жить иначе, карте важны пути в реестре `architecture/project/services.yaml`.

## Разработка

**Любое изменение системы начинается с:** `/dev`.

**SSOT:** [architecture/PROCESS.md](/architecture/PROCESS.md) — общее для всех шагов процесса изменений; сами шаги — в скиллах.

`/dev` по файлам понимает, где мы (`where.py`), и запускает нужный шаг:

| Скилл | Шаг |
|---|---|
| `/dev` | где мы → следующий шаг (вызывать в начале сессии и на «продолжи») |
| `/dev-start` | задача и решения решающего до описания |
| `/dev-describe` | изменение в `architecture/TOBE` поверх «как есть»: копии с правками, задачи, тесты, блоки; «да» решающего |
| `/dev-block <bN>` | код блока агентом по брифу, проверка основным вживую |
| `/dev-deliver` | ревью, документы, PR, merge |
| `/dev-close` | «как есть» заново, `done.py`, TOBE пуст |

Баг или инцидент — тоже `/dev`: точечное изменение внутри сервиса. Задачу записать, уточнить требования, сделать макет до кода — `/backlog`.

## Окружение компьютера

<заполнить: операционная система и оболочка; ниже — что важно на Windows с Git Bash, на другой системе удалить>

- Команды — через Bash, не PowerShell. Python — `python`.
- Кириллица в выводе Python — с `PYTHONIOENCODING=utf-8`.
- Запросы к `localhost` — с `NO_PROXY='*'`.
- Пути `/app/…` в `docker exec` из Git Bash — с `MSYS_NO_PATHCONV=1`; `docker cp` — без него (путь Windows должен остаться путём Windows).
- playwright-cli запускать из временной папки сессии: из репо он создаёт там `.playwright-cli/`; `file://` он не открывает — страницы карты для снимков отдавать `python -m http.server <порт> --bind 127.0.0.1 --directory architecture`.
- Временные скрипты — во временной папке сессии, имя с темой и датой; запись файлов с русским текстом — с `encoding="utf-8"` (без него Windows пишет cp1251).

Сценарий из многих кликов — `playwright-cli run-code`; пути внутри — видом `C:/…`; исключение в обработчике перехвата наружу не выпускать — оно роняет сессию. Подмена ответов сервиса (`page.route('**/<метод>**', …)`) — в том же `run-code`, что переход и действия: заданная отдельным вызовом к странице не применяется; ошибки обработчика собирать в массив и возвращать из сценария — иначе подмена молча пропускает запрос к настоящему сервису. Несколько вкладок и свёрнутое окно — скриптом на Node с Playwright с окном: фоновая вкладка у Playwright остаётся `visible`, скрытую делать событием `visibilitychange` с подменой `document.visibilityState`.

**Коммиты** — формат проверяет хук `commit-msg`: тип из `feat fix docs refactor test chore ci perf`; область — строчная латиница, цифры, `-`, `_`; заголовок ≤ 70 знаков, описание с маленькой буквы, без точки; пустая строка после заголовка; подвал — `Co-Authored-By:` и после него ничего. Проверка сообщения до коммита: `python .github/.instructions/commits/.scripts/validate-commit-msg.py <файл>`. Ветка изменения — `change/<имя>` (проверка имён веток её пропускает).

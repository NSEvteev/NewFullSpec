# NewFullSpec

<!-- <заполнить: при настройке проекта заменить этот файл описанием проекта — /new-project> -->

Шаблон для новых проектов, которые строятся вместе с [Claude Code](https://claude.com/claude-code): процесс изменений от разговора о задаче до слитого кода, живая карта архитектуры, бэклог с требованиями и проверки, которые держат всё это честным. Кода и сервисов в шаблоне нет: стек выбирается под проект.

Тексты процесса и скиллов — на русском.

## Что внутри

| Что | Где |

| Правила, которые Claude подгружает сам | [`.claude/rules/`](.claude/rules/) |
| Процесс изменений: шаги, ворота, кто что решает, почему так | [`architecture/PROCESS.md`](architecture/PROCESS.md), [`architecture/PROCESS-WHY.md`](architecture/PROCESS-WHY.md) |
| Карта архитектуры: как устроена система сейчас и что меняет идущее изменение | [`architecture/CLAUDE.md`](architecture/CLAUDE.md), [`architecture/STANDARD.md`](architecture/STANDARD.md) |
| Инструменты карты: сборка страниц, поиск, факты из кода, проверки | [`architecture/tools/`](architecture/tools/) |

## Как начать новый проект

1. Создать репозиторий из шаблона: кнопка **Use this template** на странице этого репозитория или
   ```bash
   gh repo create <имя> --template <владелец>/NewFullSpec --private --clone
   ```
   Копия обычным `git clone` несёт историю шаблона: тогда удалить `.git`, выполнить `git init -b main` и подключить свой `origin`.
2. В папке проекта: `make setup` (pre-commit с хуками, зависимости инструментов). Нет `make` — выполнить команды его цели `setup` из `Makefile`.
3. Открыть Claude Code и вызвать `/new-project`: он спросит имя проекта, кто принимает решения, стек и команды, заполнит настройки и `PROJECT.md`, соберёт пустую карту.
4. Записать первую задачу — `/backlog`, начать её — `/dev <задача словами>`.

## Как идёт работа

```
/backlog ─► /dev-start ─► /dev-describe ─► /dev-block b1…bN ─► /dev-deliver ─► /dev-close
требования   решения      «как будет»,      код блока и          ревью, PR,     «как есть»
до кода      человека     блоки, «да»       проверка вживую      merge          заново
```

Человек решает, что и зачем менять, и говорит «да» на описание; Claude пишет описание и код, агенты работают по брифу, а основная сессия проверяет результат вживую. Состояние лежит в файлах, а не в памяти сессии: любая новая сессия начинает с `/dev` и узнаёт, где остановились.

## Что нужно на компьютере

- Python 3.12, git, `pre-commit`, [GitHub CLI](https://cli.github.com/), Claude Code.
- Docker — если сервисы проекта запускаются через compose; `playwright-cli` — если нужны снимки интерфейса.

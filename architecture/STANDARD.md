# Стандарт письма md карты

Для пишущего — основной сессии или агента по брифу: как писать md карты «как есть» и «как будет», чтобы два пишущих написали одно и то же одинаково, а генератор и `find.py` поняли написанное. Как читать обозначения, коротко, — `CLAUDE.md`, раздел «Как читать md карты»; здесь — всё, что нужно, чтобы писать, в том числе «как будет» целиком. Все примеры — из проверочной карты `tools/samples/good/architecture/`: выдуманный магазин, сервис заказов `orders`, интерфейс `web`, платёжный шлюз `external:payments`, процесс `order-create` «Создание заказа», изменение «Оплата с повтором» в `TOBE/`. Карта проверочная, поэтому `find.py` и `mapmodel.py` зовутся на неё из корня репо с `--root <карта>/tools/samples/good/architecture`, где `<карта>` — папка карты.

## 1. Четыре правила, на которых стоит всё

1. **Одно знание — одно место.** Каждое знание словами пишется один раз, в месте из таблицы раздела 2. В других местах на него ставится ключ `[[…]]` — это указатель, а не повтор.
2. **Что генератор знает сам, не пишется.** Чей документ и к какому процессу относится — по пути файла. Вид сервиса — из реестра. Обработчик метода, поля запроса и ответа, типы колонок, значения настроек, порт, число тестов — из фактов (`.facts.json`). Обратное знание — «кто вызывает», «кто пишет и кто читает», «как работает» у метода, «где проявляется» у проблемы — генератор собирает из ссылок. Руками это не пишется нигде, в том числе в тексте раздела колонки или таблицы.
3. **Точка входа: договор — в справочнике, работа — в шагах.** У метода, функции, страницы, команды в справочнике только то, что видно снаружи: что делает, ошибки, доступ. Что они делают внутри — шаги срезов или `own.md`, у каждого из которых `Справочник: обрабатывает [[<точка входа>]]`. Шага нет (точка входа только отдаёт данные) — то, что она трогает, пишется строкой `Справочник:` в её же разделе. Одно из двух, не оба.
4. **Правило хозяина.** Знание лежит в папке того сервиса, в чей код ведёт его `Код:`. Общее хранилище (ключ Redis, папку, файл) описывает тот, кто пишет; остальные ссылаются `читает [[<хозяин>: <ключ>]]`. Вызов по сети, который делает общий пакет, — в «Связях» пакета. Проблему на стыке описывает тот, в чьём коде причина; у второго — раздел со `Смотри:`. Нашёл чужое знание — у себя не пиши: поставь ключ хозяина, а в отчёте напиши «для <сервиса>: что, откуда».

## 2. Где какое знание живёт

| Знание | Место |
|---|---|
| что сервис делает внутри процесса | срез `<сервис>/processes/<процесс>.md` |
| кто кому что передаёт и каким способом | процесс `_processes/<процесс>.md` |
| человеческое имя процесса | заголовок `# …` файла процесса |
| кто такой участник процесса | реестр и README сервиса; в процессе — только ключ |
| точка входа: что делает снаружи, ошибки, доступ | справочник сервиса |
| что точка входа трогает | шаг, который её обрабатывает; без шага — `Справочник:` в её разделе |
| как сервис зовёт другой: вход, ожидание, повторы, что делает при отказе | «Связи» в README того, кто зовёт; ручной вызов — `Вручную:` у метода |
| что хранит таблица, колонка, файл, папка, ключ; как их понимать | `storage.md` |
| настройка, число из кода, ограничитель | `settings.md`; в «Связях» и шагах — ссылкой на него |
| работа, которую запускает человек, расписание или другой сервис | процесс и срезы участников |
| работа, которую сервис запускает сам: при старте, по событию, свой цикл с момента старта | `own.md`; в `settings.md` — только «когда» и ссылка |
| проблема | `problems.md`; методы и шаги ссылаются полем `Проблемы:` |
| как общий пакет устроен внутри | `own.md` пакета |
| «почему так» | в том месте, которое оно объясняет |

## 3. Разметка

**Начало файла.** Файл начинается сразу с первого абзаца. Строки «чей это документ», ссылок наверх, шапки нет. Заголовок `# …` — только у процесса: это его человеческое имя. Пустой файл справочника — одна строка: «методов нет», «функций для подключения нет», «страниц нет», «команд нет», «хранилищ нет», «настроек нет», «проблем нет», «тестов нет».

**Первый абзац и первая фраза читаются отдельно** — генератор ставит их на другие страницы. Поэтому без «ниже», «выше», «как сказано» и без сокращений с точкой («то есть», а не «т. е.»): первая фраза кончается на первой точке. Первая фраза README — что это за сервис, коротко и без его имени: «Сервис заказов.» Первая фраза шага — что делает сервис: «Записывает заказ со статусом `new` до оплаты: …».

**Один абзац — одна строка**, без ручных переносов. Длина файла не ограничена: делится по смыслу.

**Заголовки и якоря.**

| Раздел | Заголовок | Якорь `{#…}` |
|---|---|---|
| назван именем из кода (метод, таблица, колонка, настройка, постоянная, функция, команда, адрес страницы, шаблон файла, путь папки, ключ Redis, ключ памяти браузера, папка тестов) | точно как в коде или фактах: `## POST /api/v1/orders`, `### orders.status`; у хранилищ, кроме таблиц, — приставка вида: `## Память браузера: cart` | не пишется |
| постоянный раздел: `Как устроен`, `Связи`, `Кто подключает`, `Настройки`, `Зашито в коде`, `Фоновая работа`, `Ограничители`, `Куда уходят запросы`, `Связанные процессы` | точно как в списке | не пишется |
| подраздел связи | `### → orders`, `### → external:payments`, под ним `#### <ключ метода у них>` | не пишется |
| русский заголовок: шаг среза и `own.md`, этап процесса, проблема, фоновая работа, ограничитель, другие настройки | своими словами | обязателен, в конце заголовка |

Якорь — латиница, строчные буквы, цифры, дефис, по смыслу: `accept`, `charge`, `p-no-retry`. Приставки: проблема `p-`, фоновая работа `bg-`, ограничитель `lim-`, другие настройки `other-`; у шагов и этапов приставок нет. Якорь уникален в файле, у проблемы — во всём сервисе. Якорь постоянный: заголовок можно переписать, якорь — нет, на него ссылаются процессы, «как будет» и другие сервисы.

**Номеров, которые ставит генератор, в md нет:** номер стрелки («1.6»), «шаг 3», имя блока работ «Б2». Стрелку и шаг называют адресом (`order-create#charge`, `orders/order-create#charge`), блок работ — ссылкой `[[b2]]`.

**Поля.** Поле — строка `<Поле>: <значение>`, одно поле — одна строка. Имена полей — только из списка своего вида (раздел 6); строка, которая начинается с другого слова и двоеточия, — обычный текст. Несколько ссылок — в строку через ` · `: `Справочник: пишет [[orders.status]] · пишет [[orders.paid_at]]`. Несколько текстовых значений — поле с пустым значением и сразу под ним список:

```
Ошибки:
- 422 `TOO_MANY_ITEMS` — позиций больше [[MAX_ITEMS]]
- 502 `PAYMENT_FAILED` — платёжный шлюз не ответил или отказал
```

Поле кончается на следующем поле, пустой строке или заголовке. `Код:` — последняя строка раздела. Порядок полей — как в разделе 6. Таблица — только для коротких строк одного вида: стрелки процесса, правила «куда уходят запросы», колонки файла данных.

**Порядок разделов в файле — как на странице.**

| Файл | Порядок |
|---|---|
| `README.md` | первый абзац → `Как устроен` → `Связи` (подразделы `###` — по имени того, кого зовут; `####` внутри — как методы в `methods.md`) → `Кто подключает` |
| `methods.md` | по группам, в порядке первого появления группы в фактах; внутри группы — по пути; у одного пути — GET, POST, PUT, PATCH, DELETE |
| `exports.md`, `pages.md`, `commands.md` | по алфавиту имени; `Куда уходят запросы` — последним |
| `storage.md` | таблицы по алфавиту, колонки — сразу под своей таблицей; затем файлы данных, папки, ключи Redis, память браузера |
| `settings.md` | `Настройки` → `Другие настройки` → `Зашито в коде` → `Фоновая работа` → `Ограничители`; внутри — по алфавиту без учёта регистра и ведущего `_` (`MAX_ITEMS`, `_PAYMENTS_TIMEOUT`, `STALE`) |
| `problems.md` | высокие → средние → низкие |
| срез, `own.md` | шаги в порядке работы — по стрелкам процесса |
| процесс | поля → этапы со стрелками в порядке времени → `Связанные процессы` |

## 4. Ссылки

**На код — строкой `Код:`** в конце раздела, а не внутри фраз:

```
Код: `src/orders/orders/service.py:18` · `src/orders/orders/service.py:19`
```

- Путь — от корня репо (папка над корнем карты); код вне репо — через `../`. Пути в тексте — тоже от корня репо.
- Строка указывает на действие, о котором говорит текст: вызов, запись, проверку, объявление маршрута метода, место, где поднимается ошибка. Не на комментарий и не на описание функции: описание может врать.
- Порядок ссылок — порядок утверждений в тексте.
- Вместо строки кода — живой источник, если знание взято не из кода: что смотрели, так, чтобы можно было повторить, и дата. Виды: `живая база`, `живой ответ`, `живой файл`, `живой диск`, `журнал контейнера`, `прогон тестов`, `живой Redis`, `живой /openapi.json`. Пример: `` `живая база · orders: orders, status = new — 3 строки · 2026-10-01` ``.
- Без `Код:` бывают: первый абзац файла (сводка того, что ниже), раздел-группа, настройка у сервиса с фактами (место — в фактах), фоновая работа (`Описание:` ведёт на шаг), раздел тестов; в «как будет» — всё внутри блоков `новое` и `меняется` и весь новый файл: нового кода ещё нет.

**На справочник — ключом `[[…]]`.** Ключ — заголовок раздела без приставки вида (`[[cart]]`, а не `[[Память браузера: cart]]`); у раздела с русским заголовком — якорь (`[[p-no-retry]]`).
- Свой ключ — без имени: `[[orders.status]]` в файлах orders. Чужой — с именем сервиса через «: »: `[[orders: POST /api/v1/orders]]`. В файле процесса своего сервиса нет — там все ключи с именем.
- Имена, которые есть у многих сервисов (`DATABASE_URL`, служебные методы), — всегда с именем сервиса.
- Внешний провайдер — `[[external:payments: POST /v1/charges]]`: справочника у него нет, ключ сверяется с `#### POST /v1/charges` под `### → external:payments` в «Связях» своего README.

**Строка `Справочник:`** стоит в шаге среза, в шаге `own.md` и в разделе точки входа без шага. У каждой ссылки — вид из закрытого списка:

| Вид | Когда | Пример |
|---|---|---|
| `обрабатывает` | шаг — часть работы, которую сервис делает по вызову своей точки входа: метода, страницы, функции, команды. Пишется у каждого шага этой работы, а не только у первого | `обрабатывает [[POST /api/v1/orders]]` |
| `зовёт` | шаг зовёт чужой метод по сети, функцию общего пакета или провайдера | `зовёт [[external:payments: POST /v1/charges]]` |
| `пишет` | шаг пишет таблицу, колонку, файл, ключ, память браузера | `пишет [[orders]]` — строку целиком; `пишет [[orders.status]]` — только статус |
| `читает` | шаг читает хранилище, настройку или постоянную | `читает [[MAX_ITEMS]]` |

- Ссылка на таблицу — на строку целиком: шаг записывает или отдаёт всю строку. На колонку — когда шаг смотрит или меняет только её: проверяет статус, ставит время оплаты. Задеты и те, кто пишет или читает таблицу целиком.
- Шаг `зовёт` чужой метод по сети — в «Связях» своего README нужен подраздел этого метода. Пара сверяется.
- **Ссылка без вида** — в тексте и других полях (`Ожидание: ждёт ответа до [[_PAYMENTS_TIMEOUT]]`, `Проблемы: [[p-no-retry]]`, `Смотри:`): указатель. Ключ проверяется, но в «кто пишет и кто читает» он не идёт.
- **В обратных кавычках без скобок** — значения, коды, примеры: `new`, `409`, `TOO_MANY_ITEMS`. Это не ссылки.

**Между документами** — обычная ссылка md с якорем: `[своя работа «Закрывает брошенные заказы»](own.md#stale)` — там, где нужен переход к документу, а не к ключу: `Описание:` фоновой работы, `Связанные процессы`. В столбце «внутри» процесса — короткая форма `orders#charge`.

## 5. Текст

- **Язык** — простой русский, для человека, который пользуется системой, а не пишет её код; имена из кода — в обратных кавычках. Запрещённые слова и слова, которым нужно уточнение, — в `project/settings.yaml` (`words`, `qualifiers`): например, «поток» — только «поток Redis», «поток SSE», «поток WebSocket».
- **Только «как есть сейчас».** «Почему» пишем — причину нынешнего устройства: решение, замер, ограничение провайдера, случай, после которого так сделали, — коротко, с датой, если известна, в том месте, которое оно объясняет. Историю — как было и что меняли — не пишем: она в git. Старое, что видно до сих пор (старое имя в журнале контейнера, старые строки в базе), — не история, а нынешнее состояние: его пишем. Пример: «основание — замер 2026-10-01: шлюз отвечает за 2–4 с» — оставить; «до переименования — …» — убрать.
- **Одна мысль — один шаг.** Своим шагом становится работа, у которой своя стрелка процесса (вызов, запись, показ человеку) или после которой работа идёт по другой ветке (другие стрелки). Проверки, отказы которых вызывающий просто получает ошибкой метода (`Ошибки:`), — часть одного шага проверки, сколько бы кодов ни было. В тексте шага две разные работы или в `Код:` больше десятка ссылок — знак, что шаг стоит разбить.
- **Числа.** У каждого числа есть основание: замер с датой, решение или «зашито в коде» со ссылкой. Число, которое задаёт поведение (таймаут, повторы, предел, возраст заказа), живёт в `settings.md` — в «Настройках», «Зашито в коде» или «Ограничителях»; в «Связях» и шагах — ссылкой на него: `старше [[STALE]]`. Единицы колонок — из списка `units` в `project/settings.yaml`.
- **Время.** У колонки-момента (`timestamptz`, `timestamp`) — поля `Хранится:` (в каком поясе), `Означает:` (какой момент), `Пример:`. Календарный день (`date`) — текстом раздела, без этих полей.

## 6. Файлы — по видам

Ниже — поля по порядку; **жирным** — обязательные. «Не пишется» — то, что генератор соберёт сам. Пути образцов — от `tools/samples/good/architecture/`.

### `README.md` — общее описание сервиса

- **Первый абзац** — что сервис делает и чего не делает, 2–4 фразы, без `Код:`. Появилось новое умение, которого сводка не покрывает, — сводка правится.
- `## Как устроен` — устройство сверх фактов: стек и библиотеки, если важны версии; общее о доступе; чего у сервиса нет. `Код:`.
- `## Связи` — **если хоть один шаг или точка входа зовёт чужой метод по сети**. Только исходящие вызовы по сети; обращения к хранилищам — ссылками в шагах. Подраздел на того, кого зовёт (`### → orders`, `### → external:payments`), в нём — подраздел на метод (`#### POST /api/v1/orders`).
  - у `###` — общее для всех методов: **`Подпись:`** — подпись линии на доске, до 4 слов; **`Адрес:`** — ссылка на настройку с адресом; **`Вход:`** — ключ, пропуск или «без входа»; **`Ожидание:`** — ждёт ли, сколько (ссылкой), повторы; **`При отказе:`** — что вызывающий делает, если не ответили или ответили ошибкой; `Не доходит:` — вызов есть в коде, но не доходит: почему и как проверено; текст — что важно сверх полей; `Код:` — место вызова у нас;
  - у `####` — только то, чем метод отличается от общего: поле `####` заменяет то же поле `###` для этого метода, остальные поля `###` действуют; **`Код:`**.
  - **Граница со шагом.** `Ожидание:` и `При отказе:` — что видно снаружи вызова: сколько ждёт, повторы, что вызывающий отвечает тому, кто зовёт его самого (код ответа), что показывает человеку. Что вызывающий при этом пишет у себя (статус, строку) — работа его шага; в `При отказе:` на неё — ссылка md на шаг, без пересказа. Коды ошибок вызываемого — в его `Ошибки:`.
  - **Переход браузера — не вызов.** Сервис отвечает переадресацией на чужой адрес (вход через провайдера, возврат в интерфейс) — запрос делает браузер, а не сервис. Это стрелка процесса вида `переход браузера` и шаг среза, который её делает; подраздела в «Связях» нет.
- `## Кто подключает` — **у общего пакета и библиотеки**: «сервис — как попадает (в образе, томом) — что нужно после правки». `Код:`.
- Не пишется: входящие связи, где вызов принимают, зачем зовут (это первые фразы шагов, которые зовут), список срезов, порт и команда запуска.
- Образец: `ASIS/orders/README.md`, `ASIS/web/README.md`.

### `methods.md` — методы

На каждый метод из фактов, кроме служебных (список `service_names` в `project/settings.yaml`), — `## <МЕТОД> <путь>`. Служебный метод получает раздел, только если о нём есть что сказать сверх обычного: проблема, особое поведение (проверка готовности смотрит не только сам сервис).
**`Группа:`** · `Вид:` (только у потока: `поток SSE` или `WebSocket`) · **`Что делает:`** — одной-двумя фразами, что видно снаружи · `Ошибки:` — список «код — когда» · **`Доступ:`** — кто может звать · `События:` (у потока — обязательно: событие — когда — поля) · `Поля:` — смысл полей, если имени мало · `Вручную:` — кто зовёт руками и когда · `Справочник:` — только если шага нет · `Проблемы:` · **`Код:`** — объявление метода и строки ошибок.
Не пишется: как метод работает по шагам, кто вызывает, имена и типы полей, обработчик. Образец: `ASIS/orders/methods.md`.

### `exports.md`, `pages.md`, `commands.md`

- `exports.md`, `## <функция или класс>`: **`Что делает:`** · `Аргументы:` · `Ошибки:` · `Справочник:` (если нет шага) · `Проблемы:` · **`Код:`**. Кто использует — собирает генератор из `зовёт [[<пакет>: <имя>]]`.
- `pages.md`, `## <адрес страницы>`: **`Что на странице:`** · **`Кому видна:`** · `Справочник:` (если нет шага) · `Проблемы:` · **`Код:`**.
- `pages.md`, `## Куда уходят запросы` — последним: таблица правил в порядке проверки — `префикс | куда | путь срезается | WebSocket | используется`; **`Адрес:`** — ссылки на настройки адресов; **`Код:`**.
- `commands.md`, `## <команда>`: `Аргументы:` · **`Что делает:`** · **`Кто запускает:`** · `Справочник:` (если нет шага) · `Проблемы:` · **`Код:`**.
- Образец страницы и правил: `ASIS/web/pages.md`.

### `storage.md` — хранилища

- Первый абзац (необязателен): своя база или файлы; миграции — когда запускаются.
- `## <таблица>` — **на каждую таблицу из фактов**: текст — что хранит, уникальные ключи; **`Единицы:`** — список «колонка — единица» для каждой числовой колонки, если они есть; **`Код:`**.
- `### <таблица>.<колонка>` — **только если описания колонки в базе мало или оно врёт**: как понимать; у момента времени — **`Хранится:`**, **`Означает:`**, **`Пример:`**; `Код:`. Служебные колонки (`id`, `created_at` и прочие из `service_names`) разделов не получают.
- `## Файл данных: <шаблон пути>`: текст — что в файле, как дописывается и что пересчитывается; **`Формат:`**; **`Сколько:`** — число файлов на дату (живой источник); **`Колонки:`** — таблица «колонка | тип | пустое | единица»; **`Код:`**. Колонка файла с разделом — `### <шаблон>.<колонка>`.
- `## Папка: <путь>` — путь от корня репо или от домашней папки (`~/…`), без абсолютных путей: `Путь у сервиса:` (если сервис видит её под другим путём) · текст — что где лежит · **`Код:`**.
- `## Ключ Redis: <шаблон>`: **`Тип:`** · **`Живёт:`** · текст · `События:` (у потока — обязательно) · **`Код:`**.
- `## Память браузера: <ключ>`: **`Где:`** — постоянно или на время вкладки · текст · **`Код:`**.
- Не пишется: кто пишет и кто читает (ни в тексте таблицы, ни у колонки — только ссылки с видом в шагах), типы, обязательность, умолчания, число строк, миграции списком. Образец: `ASIS/orders/storage.md`, `ASIS/web/storage.md`.

### `settings.md` — настройки и работа сервиса

Группа пишется, только если в ней есть запись; пустой файл — «настроек нет».
- `## Настройки` → `### <ИМЯ>` — на каждую настройку из окружения (по фактам): текст — что значит; `Код:` — только у сервиса без фактов.
- `## Другие настройки: <откуда> {#other-…}` → `### <имя>` — настройки не из окружения (файл пользователя, аргументы): **`Значение:`** · текст · **`Код:`**.
- `## Зашито в коде` → `### <имя>` — числа и списки, которые задают поведение: **`Значение:`** — число со словом единицы (фактов о постоянных нет) · текст — что значит и откуда число · **`Код:`**. Числа без имени в коде (литерал в запросе) — раздел по имени, под которым оно стоит в коде (`STALE` — имя запроса с часом внутри); нет и такого имени — `<функция>.<что>`: `get_github_user.timeout` — таймаут, вписанный в вызов внутри функции `get_github_user`.
- `## Фоновая работа` → `### <работа> {#bg-…}`: **`Когда:`** — при старте; при старте, дальше раз в …; при остановке; по событию: <какому>; фоном после ответа на метод; по расписанию (её запускает процесс) · **`Описание:`** — ссылка md на шаг `own.md` или среза. Саму работу здесь не описывают.
- `## Ограничители` → `### <что> {#lim-…}` — число, при превышении которого запрос режется, получает отказ или ждёт: **`Сколько:`** · **`Где действует:`** · **`Где хранится:`** · **`При превышении:`** · **`Код:`**. Прочие числа (таймаут, срок кэша) — «Зашито в коде».
- Не пишется: значения настроек и откуда они, секрет ли. Образец: `ASIS/orders/settings.md`.

### `problems.md` — проблемы

`## <проблема одной фразой> {#p-…}`: **`Важность:`** — высокая, средняя, низкая · **`Проверено:`** — воспроизведено, по коду, не перепроверено · `Смотри:` — если проблема описана у другого сервиса (тогда текста и `Код:` нет) · текст — что не так и чем грозит при нашем использовании · **`Код:`** — где это видно.
Не пишется: где проблема проявляется — это поля `Проблемы:` методов и шагов. Образец: `ASIS/orders/problems.md`.

### `tests.md` — тесты

`## <папка тестов из реестра>` — почему тесты такие: что падает и почему, что пропущено и почему, чего тесты не проверяют. Число тестов и итог прогона — факты. Тесты есть, а сказать о них нечего — одна строка «пояснений нет»; тестов нет совсем — «тестов нет». Образец: `ASIS/orders/tests.md`.

### `processes/<процесс>.md` — срез

**Где живёт работа точки входа.** Работа, которую запускает человек (со страницы), расписание или другой сервис, — шаги в срезе процесса, где её запускают. Такого процесса нет — его заводят: действие человека на странице — процесс человека, первая стрелка `human → <интерфейс>`. `own.md` — только для работы, которую сервис запускает сам.

Срез заводится, где у сервиса есть работа внутри процесса: пишет, зовёт, меняет состояние, считает, решает, показывает человеку. Если сервис только отдаёт данные методом — среза нет, в «внутри» у стрелки стоит ключ метода.
- **Первый абзац** — что сервис делает в этом процессе, 1–3 фразы.
- `## <шаг> {#…}` — **хотя бы один**, в порядке работы: текст (**первая фраза** — что делает сервис) · `Справочник:` · `Проблемы:` · **`Код:`**.
- `Код:` шага — только свой код. Шаг зовёт функцию общего пакета — `зовёт [[<пакет>: <функция>]]`, а что функция делает внутри, пишет пакет (`own.md`, `exports.md`) со своим `Код:`.
- Не пишется: ожидание, повторы и что видно снаружи при отказе (это «Связи»; шаг пишет, что сервис при этом записывает у себя), что делает другой сервис (его срез) или вызванная функция пакета, стрелки, ведущие на шаг. Шаг, который делает вызов по стрелке, есть у обоих: у того, кто зовёт (`зовёт …`), и у того, кто принимает (`обрабатывает …`).
- Образец: `ASIS/orders/processes/order-create.md`, `ASIS/web/processes/order-create.md`.

### `own.md` — своя работа вне процессов

Работа, которую сервис запускает сам: при старте, по событию, свой цикл с момента старта («раз в 10 с, пока работает»); у общего пакета — ещё как он устроен внутри. Вид — как у среза: первый абзац, шаги `## … {#…}` с `Справочник:`, `Проблемы:`, **`Код:`**. Образец: `ASIS/orders/own.md`.

### `_processes/<процесс>.md` — процесс

- **`# <название>`** · **первый абзац** — зачем человеку, что происходит, чем кончается.
- Поля по порядку: **`Кто запускает:`** — действие человека (страница, кнопка) или расписание; кому можно · **`Чем кончается:`** — что где лежит после, что видит человек · **`Работает ли сейчас:`** — да, нет или частично, с датой живой проверки и id проверенных стрелок · `Не происходит:` — список «id — почему» стрелок, которых сейчас нет по причине вне связи · **`Участники:`** — ключи через ` · ` в порядке дорожек: `human`, `schedule`, сервисы, `external:<провайдер>`, `redis`, `folder:<путь>` · `Группа:` — одна из `process_groups` в `project/settings.yaml`.
- `## <этап> {#…}` — **хотя бы один**: пояснение абзацем (необязательно) и таблица стрелок `| id | кто → кому | что | как | вид | внутри |`:
  - `id` — постоянный, латиницей, уникален в процессе вместе с якорями этапов;
  - `кто → кому` — ответ на запрос — часть той же стрелки, отдельной не пишется. Событие потока (метод с `Вид: поток SSE` или `WebSocket`) — своя стрелка от сервера к клиенту: событий много и у каждого свой смысл; «как» — ключ метода потока, «внутри» — шаг сервера, который его обрабатывает, и шаг клиента;
  - `что` — что передаётся, до ~8 слов: это подпись на схеме;
  - `как` — ключ с именем сервиса: метод, таблица, ключ Redis, файл; у провайдера — ключ его метода; у стрелки человека — ключ страницы и что он на ней делает (`[[web: /orders]], кнопка «Оформить»`); у петли `внутри сервиса` — пусто;
  - `вид` — `человек`, `запрос`, `переход браузера`, `внешний провайдер`, `Redis`, `файл`, `база`, `внутри сервиса`; петля «сервис → сам себе» — только `файл`, `база`, `внутри сервиса`;
  - `внутри` — `<сервис>#<якорь шага>` отправителя и получателя или ключ метода без шага; к хранилищу и провайдеру — шаг отправителя; к человеку и от человека — шаг интерфейса. Каждый шаг среза стоит хотя бы в одном «внутри».
- `## Связанные процессы` — список «как связан — ссылка»: `- идёт после [«Создание заказа»](order-create.md): отменяет заказ, который тот записал`. Достаточно с одной стороны — у того процесса, которому связь нужна, чтобы его понять.
- Ключ процесса — латиницей по смыслу, через дефис (`order-create`); этим же ключом названы все его срезы.
- Не пишется: номера стрелок, проблемы на стрелке, поведение вызова. Образец: `ASIS/_processes/order-create.md`.

### Особые сервисы

- **Общий пакет** — та же папка; главное — `exports.md`; в README — «Кто подключает» и «Связи», если пакет сам зовёт кого-то по сети; как устроен внутри — `own.md`; срез — где пакет сам участник процесса.
- **Интерфейс** — страница, которая не ложится ни в один процесс, становится своим процессом человека («Работа со страницей …»): стрелки — действия человека и запросы страницы, что страница делает у себя — её срез.
- **Сервис без фактов** (`facts: []` в реестре) — всё о нём в md: у настроек есть `Код:`.

## 7. «Как будет»

Идущее изменение лежит в `TOBE/`. Полный пример — изменение «Оплата с повтором» в `TOBE/` проверочной карты.

### 7.1 Файлы

| Файл | Что в нём |
|---|---|
| `TOBE/README.md` | обложка: что меняем и зачем, решения, что не задето, судьбы проблем, последствия для процессов (7.6) |
| `TOBE/<путь как в ASIS>` | копия задетого файла «как есть» с правками блоками (7.2–7.3) или новый файл |
| `TOBE/<сервис>/tasks.md` | задачи и тесты сервиса (7.7) |
| `TOBE/blocks.md` | блоки работ (7.8) |
| `TOBE/board.yaml` | судьба узлов доски; поля — в шапке файла образца |

**Объём «как будет» = объём изменения.** Копию получает только файл, чьё содержимое меняется. Процесс, у которого не меняются ни стрелки, ни поля, а меняется только то, что генератор подтягивает из справочников и «Связей» на страницу карты, — строкой в «Последствиях для процессов» на обложке, без копии.

**Доска — `TOBE/board.yaml`.** Узел вызывающего — `changes`, если в его «Связях» появился или ушёл подраздел `###` или `####`, хранилище или подключение; узел вызываемого — `changes`, только если к нему появилась или ушла линия. Новая работа внутри сервиса — не повод. Поля узла — в шапке файла образца.

### 7.2 Копия и новый файл

- **Задетый файл** копируется из `ASIS/` в `TOBE/` под тот же путь целиком, и правки стоят в нём блоками на месте. Вне блоков копия совпадает с «как есть» байт в байт.
- **Новый файл** (новый процесс, срез, `own.md`, сервис) лежит в `TOBE/` без пары в `ASIS/`. Первая строка — `Правка: c-… · <статус>`, вторая — `Почему: …` (как у блока), пустая строка, дальше — как обычный файл этого вида: у процесса с `# <название>`. Весь файл — одна правка `новое`; `Код:` в нём при описании не пишется — его ставит блок (7.3). Часть, у которой статус слабее, чем у файла, оборачивается своим блоком. У нового процесса `Работает ли сейчас: нет — процесс появится с этим изменением`. Пример:

```
Правка: c-ord-cancel-slice · решено владельцем
Почему: [[d-cancel]]

orders отменяет заказ, который ещё не оплачен: ставит ему статус `cancelled`.

## Отменяет заказ {#cancel}

Ставит заказу статус `cancelled`, только если он всё ещё `new`.
Справочник: обрабатывает [[DELETE /api/v1/orders/{order_id}]] · пишет [[orders.status]]
```
- **Файл, который уходит целиком**, — копия, обёрнутая одним блоком `уходит`.

### 7.3 Блок правки

```
::: <вид> <номер> · <статус>[ · вместо <ключ>]
<что обёрнуто>
Почему: …
:::
```

- **Вид:** `новое` — такого не было; `меняется` — внутри новое значение, «было» генератор найдёт в «как есть» на том же месте; `уходит` — внутри то, что уходит, как было.
- **Что можно обернуть:** раздел целиком с заголовком — один или несколько подряд; поля одного раздела (заголовок — вне блока); строки таблицы стрелок; текст без полей — сводку файла или абзацы раздела. Блоки не вкладываются.
- **`меняется` раздела целиком** — внутри раздел, каким он станет. Поля, которых в нём нет по сравнению с «как есть», уходят этой правкой; исключение — `Код:`: до блока его в правке нет, и это не значит, что он уходит.
- **Правка пишется так, как будет стоять в «как есть»:** закрытие переносит её командой (`map.py apply`), не переписывая. Отсюда два правила:
  - **«почему» — словами в тексте правки**, в том месте, которое оно объясняет («…номер страница помнит, а «Оформить» не даёт, чтобы покупатель не оформил заказ второй раз»), один раз;
  - **без слов истории** — «больше не», «теперь», «по-прежнему», «как раньше»: в «как есть» они станут враньём о прошлом. Проверка «как будет» предупреждает о них (25.17).
- **`Почему:`** — последняя строка блока, всегда, только ссылки — проверка предупреждает о тексте в ней (25.18):
  - правка следует из решений — пунктов требований с якорем `{#d-…}` — ссылки на них через ` · ` (`Почему: [[d-retry]] · [[d-poll]]`); так у любого статуса;
  - решение по рекомендации без пункта в требованиях — `Почему: по рекомендации`, а что решил пишущий и почему — в тексте правки;
  - открытый вопрос — ссылка на пункт `(открыто)` в требованиях: варианты с ценой — там, а в самой правке — рекомендуемый вариант.
- **`Код:` в `новое` и `меняется` при описании не пишется**: нового кода ещё нет. Его ставит блок, который написал код: `map.py code <копия>#<раздел> <путь:строка>…` — у каждого раздела правки «новое» и «меняется» целиком и у разделов нового файла (без него — те же разделы, что и в «как есть»: первый абзац, фоновая работа, раздел-группа, настройка из фактов, тесты, файлы процессов); что осталось без `Код:` — `map.py code --gaps <блок>`. Правка полей или текста внутри раздела `Код:` не получает: строку `Код:` раздела вне блока после блоков переносит и проверяет закрытие (`relocate.py`, `live.py`).
- Ключ, которого нет в `ASIS/` (`[[PAYMENTS_RETRIES]]`), — новый: он есть в `TOBE/`.

### 7.4 Номера

| Что | Номер | Пример |
|---|---|---|
| правка в файле сервиса | `c-<короткое имя сервиса из реестра (short)>-<смысл>` | `c-ord-charge` |
| правка в файле процесса | `c-<сокращение процесса — первые буквы слов ключа>-<смысл>` | `c-oc-end` — `order-create`, «Чем кончается» |
| решение — якорь пункта требований | `d-<смысл>` | `d-retry` |
| задача | `k-<short>-<смысл>` | `k-ord-retry` |
| тест | `t-<short>-<смысл>` | `t-ord-retry` |
| блок работ | `b1`, `b2`… по порядку | `b2` |

Номера уникальны во всём изменении и пишутся без имени сервиса из любого файла `TOBE/`: `[[c-ord-charge]]`, `[[k-ord-retry]]`, `[[b2]]`. Сокращения двух процессов изменения совпали (`order-create` и `order-cancel` — оба `oc`) — у второго берутся первые слоги: `ocan`.

### 7.5 Статусы

Слова статусов — список `statuses` в `project/settings.yaml`, от сильного к слабому; кто решает — `decider` там же:
- решение того, кто решает (`решено владельцем` в проверочной карте) — его слова дословно в пункте требований: «владелец, <дата>: «…»» или «выбрал «<вариант>»» (проверка 25.5). Решение — это его слова **и текст решения**, на который он сказал «да»: вариант, показанный ему со всеми числами и краями (три попытки, ответ 202, раз в 10 с), и то, что он сам поставил задачей (коды, переходы статусов из постановки). Подробность, которой нет ни в словах, ни в тексте решения, — не его решение: `решено по рекомендации` (то, чего человек не видит: имена в коде, заголовок запроса, порядок проходов) или `предложено` (что он увидит: сумма, текст, код ответа);
- `решено по рекомендации` — пишущий решил сам то, что не меняет видимого человеку и не задевает границ механизма;
- `предложено` — всё остальное, что предлагает пишущий: подробности сверх слов и постановки (код ответа на краю, вход, текст на странице);
- `открыто` — вопрос; варианты с ценой — вложенным списком у пункта требований.

В требованиях статус — пометка пункта: без пометки — решение того, кто решает; `(по рекомендации)`; `(не согласовано)` — статус «предложено»; `(открыто)` (`PROCESS.md`, 6.4).

- **Статус правки — самый слабый из решений, на которые она ссылается** в `Почему:`: опирается на `предложено` — сама `предложено`.
- **Решённое и предложенное в одном разделе.** В существующем разделе поля, которые следуют из разных решений, — разными блоками полей. Новый раздел — один блок со статусом самого слабого из его решений; что из него решено, видно по ссылкам в `Почему:`.
- `открыто` и `предложено` держат «да» на всё описание: код начинают только после строки `Описание утверждено:` на обложке.

### 7.6 Обложка — `TOBE/README.md`

```
# <название изменения>

<что меняем и зачем — 2–4 фразы: что сейчас не так, что будет>

Ветка: change/<имя>
PR: #<номер>
Требования: <ссылки на задачу изменения в _backlog/: промт и папка>
Описание утверждено: <дата> · <коммит> · «<слова человека>»

## Решения

- [[d-…]] — <решение одной фразой, сжато>

## Не задеты

- <что могло бы быть задето> — <почему не задето>

## Судьбы проблем

- [[<сервис>: p-…]] — закрывает [[c-…]]; раздел проблемы уходит — [[c-…]]
- [[<сервис>: p-…]] — остаётся: <почему; где ещё проявится> — [[c-…]]
- [[<сервис>: p-…]] — новая — [[c-…]]

## Последствия для процессов

- `<процесс>` «<название>» — что для него меняется и почему его файла нет в `TOBE/`
```

- `Ветка:` — ветка изменения; `PR:` — номер, когда открыт; `Требования:` — ссылка на набор требований изменения (файл или `README.md` папки — тогда все md папки): из него читаются решения и вопросы к тому, кто решает; `Описание утверждено:` ставит основная сессия, когда человек сказал «да».
- **«Решения»** — строка на решение, на котором стоит описание: `- [[d-…]] — <сжато>`. Статуса, слов и вариантов на обложке нет: они в пункте требований с якорем `{#d-…}` (`PROCESS.md`, 6.4) — два места со статусом расходились, и «открыто» в одних требованиях проверки не видели. Пункт требований: `- (решено) **<решение одной фразой>** {#d-…} (<имя>, <дата>: «<слова дословно>»): <что решено — с числами и краями>`; ответ выбором варианта — «выбрал «<подпись варианта>»»; у `(открыто)` — варианты с ценой вложенным списком `- <вариант>. Цена: …`, рекомендуемый первым с «(рекомендую)»; `(предложено)` — `- (предложено) **<что>** {#d-…} (<дата>): <что и почему>`, без имени. Строка на обложке — у каждого пункта с якорем, в том числе открытого и предложенного.
- **«Не задеты»** — то, что `find.py --chain` и `--process` по задетым ключам показывают как задетое, но что изменение на деле не меняет, — с причиной. Так видно, что задетое просмотрено, а не забыто.
- **Проблема, у которой меняется текст** (`меняется`), — если дописанное не проверено, поле `Проверено:` идёт в тот же блок со словом «не перепроверено».
- Раздела нет, если сказать нечего.

### 7.7 Задачи и тесты — `TOBE/<сервис>/tasks.md`

```
## Задачи

### <задача> {#k-…}
`<путь от корня репо>`: <что сделать в коде — имена, значения, поведение в краях>
Правки: [[c-…]] · [[c-…]]
Тесты: [[t-…]]
После: [[k-…]]
Удаляется: <что уходит из кода>

## Тесты

### <тест> {#t-…}
<что делает тест и что проверяет>
Набор: <папка тестов из реестра или «проверка вживую»>
Вид: новое | меняется | уходит
Тест: <имя теста в коде — у «меняется» и «уходит» с описания; у «новое» — после блока>
Проверяет: [[c-…]] · [[c-…]]
```

- **`Правки:`** — какие правки файлов сервиса задача делает правдой, в том числе правки только md (сводка, фоновая работа): их правдой делает код. Каждая правка файлов сервиса — ровно в одной задаче. Правки файла процесса и обложки в задачи не входят: процесс становится правдой через срезы, на которые ведут стрелки.
- `После:` — задачи, которые должны быть сделаны раньше; `Удаляется:` — если задача что-то убирает в коде. В `Удаляется:` в обратных кавычках — только удаляемое (файл, функция, класс, команда): проверка 25.8 ищет каждое такое имя в коде; новые имена в пояснении — без кавычек. «Уходит» только в md (раздел проблемы, поле) — без `Удаляется:`.
- `Тест:` у `меняется` — имя теста в коде; блок переименовал тест — в `Тест:` новое имя (по нему закрытие ищет тест в коде). У `новое` имени нет, пока тест не написан. Имена дописывает основная сессия, проверив блок: агент блока md не правит (7.9). Несколько тестов — через « · »; поэтому имя с « · » внутри (заголовок `describe` вида «база · (1 + …)») закрытие режет на куски и не находит — такое имя пишется заголовками `it` без « · ».
- У каждого теста `Проверяет:` хотя бы одну правку; у каждой задачи — хотя бы один тест или запись в тексте, почему теста нет.

### 7.8 Блоки работ — `TOBE/blocks.md`

```
## <сервис>: <что> {#b1}
Где: <сервис>
Задачи: [[k-…]] · [[k-…]]
После: [[b…]]
<что правда после блока; чем рискуем между блоками>
Готово, когда: <проверка: тесты [[t-…]], ruff, живая проверка>
```

Блок делает один агент; каждая задача — ровно в одном блоке. Отметку `Сделано:` ставит основная сессия, когда блок проверен.

Последним, без якоря, — `## После блоков` (если есть что сказать): что делается после всех блоков, до ревью и PR, — документы соседних репо, которые изменение делает неверными (путь и раздел), и кто их правит.

### 7.9 Кто пишет

«Как будет» пишет основная сессия (или агент описания своей папки). Агент блока работ md не правит: расхождение с описанием — заметкой в отчёт, основная сессия вносит правкой.

## 8. Готово, если

«Как есть»:
- `python <карта>/tools/build.py` — у твоих файлов 0 ошибок; `python <карта>/tools/mapmodel.py --stubs ASIS/<сервис>` (путь — от папки карты) — заглушек нет.
- `find.py --service <сервис>` и `find.py --process <процесс>` — без предупреждений о расхождениях (участник без стрелок, срез без строки в `Участники:`).
- У каждой точки входа есть шаг, который её `обрабатывает`, или своя строка `Справочник:`; у каждого вызова по сети из шагов — подраздел в «Связях».
- Каждая ссылка `Код:` открыта и указывает на действие, о котором говорит текст.
- В тексте нет обратного знания («пишет …», «читает …», «вызывает …» руками), истории и чисел без основания.
- Страница сервиса или процесса открыта и прочитана глазами: `python <карта>/tools/open.py <что>`.

«Как будет»:
- `build.py` — 0 ошибок «как будет»; заглушек нет.
- У каждой правки файла сервиса есть задача, у каждой задачи — блок (проверки 25.6–25.7 при сборке); `find.py <c-…> --tobe` — у каждой правки «меняется» «было» и «станет» различаются.
- Каждое решение, на которое ссылаются правки, есть на обложке; статусы правок не сильнее решений.

# Стандарт кода

Один короткий стандарт: здесь только то, что правда про наш код и что мы реально ловили. Образец всегда — соседний код того же сервиса: пиши так, как уже написано рядом, если здесь не сказано иначе. Как вести изменение (ветка, коммиты, проверки) — `architecture/PROCESS.md`.

Разделы под стек — заготовка из проверенного опыта: `/new-project` оставляет свои и удаляет чужие, остальное дополняется по мере находок.

## Что проверяется машиной

- <заполнить: линтер и форматтер, их настройки и команда перед коммитом; проверка типов>
- **Тесты** — только своего пакета и только командой из `PROJECT.md`, «Команды», с потолком памяти: без потолка прогон тестов однажды занял 16+ ГБ и дважды уронил компьютер.
- Проверка, записанная в настройках, но нигде не запускаемая, — не проверка: не ссылаться на неё.

## Общее для всего

- Просто и сейчас: самое понятное решение, без параметров и абстракций «на будущее»; дублирование больше нескольких строк — в общую функцию.
- Исключения не глушить: без пустых обработчиков; ошибка — наружу или в лог с контекстом.
- Правка чужого кода — только рядом с тем, что меняешь: не переписывать работающее ради стиля.
- Выключенное = удалённое: код, до которого выполнение больше не доходит, удаляется в том же изменении, со списком `Удаляется:` в задаче «как будет».
- Проверка результата — числом или выводом, а не словом «успех»; новую проверку — проверить на испорченном входе (`architecture/PROCESS.md`, раздел 7).
- Сверка расчёта «точно» — в том же окружении, что считало: версии библиотек в контейнере и на компьютере бывают разные.
- Комментарий объясняет «почему», а не пересказывает строку.
- Значения секретов — никогда в код и в вывод. Новая переменная окружения — в `.env.example` с рабочим значением для разработки, секрет — заглушкой.
- Адреса других сервисов — из настроек, не зашиты в код.

## Python

- Точные версии пакетов закреплены; версия Python одна в сервисах и образах.
- Именование — как в PEP 8: модули и функции `snake_case`, классы `PascalCase`, константы `SCREAMING_SNAKE`, исключения — с суффиксом `Error`.
- Настройки — `pydantic-settings` в `config.py` сервиса. `print()` — только в утилитах командной строки.

## Сервисы (FastAPI)

- Методы — в `api/v1/<тема>.py`, логика — в `services/`, база — в `repositories/`; метод только принимает, проверяет и отдаёт.
- Схемы запросов и ответов — Pydantic v2, у запросов `extra="forbid"`: опечатка в поле — 422, а не тихое «поле проигнорировано».
- Ошибки — единым форматом, как у остальных методов сервиса.
- Один HTTP-клиент на сервис, а не новый на каждый вызов. Повторов на 401 и 403 нет: это ошибка настройки, а не сбой.
- **Тяжёлое не делать в `async def`**: долгий расчёт и синхронный HTTP блокируют весь сервис. Короткое — `asyncio.to_thread`; расчёт — отдельный процесс задачи.
- Глобальное состояние в модулях не множить: новые зависимости — через `Depends`, `app.state`.

## База и Redis

- У каждого сервиса своя база, схема меняется только миграцией в папке сервиса. Колонкам — описание (`comment`), его читает карта.
- Параметры запросов — только связанными переменными, без подстановки строк в SQL.
- Живые базы и Redis при проверках — только чтение (база — `select`; Redis — `SCAN`, `TYPE`, `XLEN`, `XINFO`, `ZCARD`, `EXISTS`; `KEYS *` — никогда).

## Docker

- Образы с закреплённой версией, без секретов в `ENV` и `ARG`.
- Если код смонтирован томами и запущен с автоперезапуском: правка файла сразу меняет живой сервис, переключение ветки — тоже. Перед `git switch` смотреть, какой код поедет в контейнеры.
- Команда запуска — через `exec <команда>`: иначе первым процессом контейнера остаётся `sh`, `docker stop` не доходит до сервиса, и мягкой остановки нет.
- У каждого сервиса есть healthcheck в compose; `depends_on` — только с `condition: service_healthy`: без условия он гарантирует порядок запуска, а не готовность.
- Без `.dockerignore` сборка на Windows зависает.
- `pydantic-settings` читает `list[str]` из переменной как JSON: `["a","b"]`, не `a,b`.

## Интерфейс (React, TypeScript)

- Данные с сервера — `@tanstack/react-query`: ключ запроса включает все параметры. Состояние интерфейса — отдельно от данных сервера; подписка — на нужный кусок хранилища, а не на всё.
- Ответы сервера проверяются схемой. Договор данных живёт сразу в нескольких местах (сервер, типы, схема) — правится во всех, иначе схема молча выкинет новое поле.
- Без `any`, без `!` и `as T` без проверки; компоненты — именованным экспортом.
- На Windows Vite следит за файлами опросом (`usePolling`) — не выключать: без него он падает на томе Docker.
- Что видит человек, проверять снимком браузера, а не по коду: «показывает ошибку» и «показывает общее «Запрос не выполнен»» — разные вещи.

## Внешние провайдеры данных

- Документацию провайдера читать при каждой работе с ним; официальный клиент предпочтительнее голого HTTP, его синхронные методы из async-кода — через `asyncio.to_thread`.
- После переподключения подписки восстанавливать; постраничный ответ проходить до конца; повторов на 401 нет.

## Установка

После клонирования — `make setup`; настройка проекта — `/new-project`; окружение — `/docker-up`.

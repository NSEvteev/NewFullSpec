# Проверочная карта good — выдуманный магазин

Маленькая чистая карта, на которой инструменты карты проверяют сами себя. На ней:
- **все проверки молчат** — 0 ошибок и 0 предупреждений. Заговорила проверка — значит, она начала срабатывать зря, или карту испортили;
- **поиск и «где мы» отвечают ровно как в ожидаемых файлах** — ответы `find.py` и `where.py` сравниваются с ними побайтно;
- **мир «как будет» даёт ожидаемый результат** — копии из `TOBE/` с раскрытыми правками заменяют задетые файлы «как есть», и итог сверяется с готовым.

Карта едет в общий набор: по ней новый проект видит, как выглядят md карты, и проверяет, что инструменты у него работают. Поэтому проект выдуманный, а имён настоящего проекта в ней нет.

Для каждого правила проверки есть ещё испорченная карта — `../bad/<правило>/`: на ней это правило обязано сработать.

## Что внутри

```
good/                         маленькое репо
├── README.md                 этот файл
├── architecture/             корень карты (здесь project/settings.yaml)
│   ├── project/              реестр, доска, настройки магазина
│   ├── ASIS/                 «как есть»
│   │   ├── orders/           сервис заказов: с фактами (.facts.json)
│   │   ├── web/              интерфейс: без фактов, одни md
│   │   └── _processes/       процесс «Создание заказа»
│   └── TOBE/                 «как будет» на два блока
├── expect/                   ожидаемые ответы инструментов: find/ — ответы find.py
└── src/                      код магазина: на его строки ведут ссылки «Код:»
```

Корень репо для ссылок «Код:» — папка над корнем карты, то есть `good/`: ссылка `src/orders/orders/api.py:13` ведёт в `good/src/orders/orders/api.py`, строку 13.

## Что показывает

| Вид | Где |
|---|---|
| сервис с фактами и без фактов | `orders` (`.facts.json`) и `web` (`facts: []` в реестре) |
| общее описание: «Как устроен», «Связи» с сервисом и с внешним провайдером | `orders/README.md` → платёжный шлюз; `web/README.md` → orders |
| метод с `Справочник:` и метод, который обрабатывают шаги; `Вручную:` | `GET /api/v1/orders/{order_id}` и `POST /api/v1/orders` в `orders/methods.md` |
| служебный метод без раздела | `GET /api/v1/health` — есть в фактах, раздела нет |
| пустой файл справочника — одна строка | `orders/exports.md`, `web/methods.md` и другие |
| таблица, колонка, поля времени, единицы | `orders/storage.md` |
| память браузера | `web/storage.md` |
| страница и правила прокси | `web/pages.md` |
| настройки, зашитое в коде, фоновая работа, ограничитель | `orders/settings.md` |
| проблема и ссылки на неё | `orders/problems.md` ← шаг `charge`, своя работа `stale` |
| тесты: почему такие | `orders/tests.md` |
| своя работа вне процессов | `orders/own.md` |
| срезы обоих участников; шаги, которые обрабатывают, зовут, пишут, читают | `orders/processes/order-create.md`, `web/processes/order-create.md` |
| процесс: два этапа, стрелки всех видов участников — человек, запрос, база, внешний провайдер | `_processes/order-create.md` |
| «как будет» — изменение «Оплата с повтором»: обложка с решением и предложением, задачи, тесты, блоки, доска | `TOBE/README.md`, `TOBE/*/tasks.md`, `TOBE/blocks.md`, `TOBE/board.yaml` |
| правки: поля метода, связи и процесса (`меняется`); новая постоянная, шаг, этап, метод связи (`новое`); проблема, шаг, стрелка, поле (`уходит`) | копии в `TOBE/orders/`, `TOBE/web/`, `TOBE/_processes/` |

Чего здесь нет: функции для подключения, команды, файла данных, папки, ключа Redis, других настроек, общего пакета, процесса по расписанию. Их форма показана в испорченных картах и в описании настоящего проекта.

## Как прогнать

Из корня репо:
- `python architecture/tools/build.py --root architecture/tools/samples/good/architecture` — должно быть 0 ошибок и 0 предупреждений;
- `python -m pytest architecture/tools/tests` — модель и сборка на этой карте; ответы `find.py` сверяются с `expect/find/` (как устроены эти файлы — `expect/README.md`); ответы `where.py` встанут туда же, когда появится команда.

## Как менять

- Код в `src/` не собирают и не запускают: он нужен только затем, чтобы ссылки «Код:» вели в настоящие строки. Поменял код — поправь номера строк в md в том же коммите.
- `.facts.json` сервиса orders написан руками в том виде, в каком его выдаёт скрипт фактов: в проверочной карте живой системы нет.
- Новый вид документа или раздела в карте — добавь его сюда, иначе проверки этого вида на чистой карте не проверяются.
- Без имён настоящего проекта: карта едет в другие проекты, и проверка общего набора ищет эти имена и здесь.

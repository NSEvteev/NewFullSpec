# Ожидаемые ответы инструментов на проверочной карте good

Что здесь. Ответы команд карты на проверочной карте `../architecture/` — файлом на случай. Тест запускает команду и сравнивает её вывод с файлом строка в строку: разошлось — значит, либо команда сломалась, либо её поменяли нарочно, и тогда файл переписывают и читают разницу глазами.

- `find/` — ответы `find.py`: по файлу на режим и случай; что покрыто — видно по именам файлов (`01-key-method.txt`, `22-chain-column.txt`, `32-tobe-key-gone.txt`…). Сверяет их тест `tools/tests/test_find.py`.
- `where/` — ответы `where.py`: по папке на состояние изменения (`01-no-change`, `07-approved-block1`, `11-delivery`…); в папке `case.yaml` — как из этой карты получить состояние (те же `remove`, `replace`, `add`, что у испорченных карт `../../bad/`) и `expect.txt` — команда, код выхода и вывод. Сверяет их тест `tools/tests/test_states.py`, переписывает — он же с `--update`.

## Файл ответа

Имя — `find/<номер>-<случай>.txt`: номер — следующий по порядку, случай — латиницей через дефис. Тест берёт только файлы `find/*.txt`; файл в другом месте или с другим расширением он молча пропустит.

```
$ find.py 'orders: POST /api/v1/orders'
# код выхода 0
orders: POST /api/v1/orders — нашлось
…
```

- строка 1 — команда, как её набирают в Bash: `$ find.py <аргументы>`; первое слово после `$` — ровно `find.py`; ключ карты — в одинарных кавычках; `--root` не пишется — тест подставляет его сам;
- строка 2 — `# код выхода N`;
- дальше — то, что команда печатает в stdout. Предупреждения (stderr) не сверяются.

Пути в ответах — от `good/`: `architecture/ASIS/orders/methods.md:1`.

## Как прогнать

Из корня репо:
- `python -m pytest architecture/tools/tests/test_find.py -q` — сверка всех ответов;
- один случай — `-k 01-key-method`; с разницей ответа и файла — `-vv`.

## Как добавить случай

1. Создать файл `find/<номер>-<случай>.txt` с двумя первыми строками; в строке 2 — любой код выхода, после неё — перевод строки.
2. `python architecture/tools/tests/test_find.py --update` — допишет ответ и код выхода. Команда переписывает **все** файлы `find/` текущим выводом `find.py`, поэтому перед ней свои незакоммиченные правки в `find/` лучше закоммитить.
3. Прочитать новый файл глазами: `--update` делает эталоном то, что команда печатает сейчас, вместе с её ошибками. Верен ли ответ — решает тот, кто добавляет случай.
4. `git diff` по `find/` — остальные файлы не должны были измениться; прогнать тест.

## Если разошлись многие ответы

Сначала посмотреть разницу без переписывания: `-vv`, по одному случаю `-k`. Команда сломалась — чинить команду, файлы не трогать. Её поменяли нарочно — `--update`, затем прочитать весь `git diff` по `find/`: каждая изменённая строка должна объясняться правкой.
